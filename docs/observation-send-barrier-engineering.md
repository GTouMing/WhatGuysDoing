# 世界数据发送屏障：入口、同步候选与证明缺口

## 一、本轮结论与范围

本稿保留当前真实发送入口、HTTP/WebSocket 公式及 K 条件证明；[R19-Q162／ADR-0011](<adr/0011-public-read-only-observation.md>) 已取消观察认证、凭证撤销／交付和授权文件恢复，所以下文涉及这些职责与原 Q157 的 PUBLIC 相对真实授权公平仅为旧方案推演，不再是公开服务实施门。现行迁移见[公开访问合同](<observation-public-access.md>)：独立的单一输出所有者、受影响服务／页停止、有限写、全站／每页包络和实际收束仍保留，R20-Q163–Q165 已分别确认正常启动／重启在 enabled 且真正就绪时自动公开、显式对外绑定内置数据端口及页等份公平。配置关闭、真实故障、残留未退出不绕过；R21-Q166 已确认真故障只停观察、游戏继续，仅在故障消除、相关旧输出／写入收束且重新就绪后有限自动重建当前；未知或耗尽保持关闭并提示管理员，不无限重试／回放。无观察者认证、不强制回环，远程 WebGPU 仍同源 HTTPS/WSS、保持非嵌入；R21-Q168 已定运营者反向代理负责 HTTPS/WSS／证书，模组不内置证书管理，具体代理产品／配置未选、不部署。R21-Q169 剩余服务／故障／概览代次管理仅服务器控制台和受控配置，不做网页／游戏内管理或授权者名单。没有产品修改、构建、运行或新的验证执行批次；静态原始资料读取不是网络／平台运行实验。[开工包](<observation-kickoff.md>)及[V2 草案](<observation-verification-v2.md>)只组织后续工作，不是实施或验证许可。

继续分析的具体候选是“单一网络输出所有者＋非阻塞通道＋显式待写片段”。Q155–Q156 已接受一个明确的输出所有者线性化点及请求后的唯一一次 `K` 有界写；这解决政策含义，不证明代码、固定平台或硬退出已经满足条件。

沿用 Q155–Q156 的发送屏障线性化；R20-Q163 已用 enabled 且真正就绪时随正常启动／重启自动公开替代 Q154 每次人工开通（旧规则仅历史）：R 立即拒绝受影响新准入和输出生产，全站一个此前获准、输入≤K的通道调用可返回，下一写前建立匹配 B；B 不是实际引用／连接／生产者退出。游戏不等待磁盘或网络，实际必要持久职责另核。应用缓冲后缀不是 R 前已交 OS／代理字节，已提交字节也不承诺收回。旧 Q67／Q146 观察授权保存步骤撤出；R20-Q164／Q165 的外部绑定与页等份边界已确认，K、具体调度与完整容量仍未核定，没有新增预算、部署或实施许可。

## 二、已亲自核对的真实发送入口

范围是当前内嵌 HTTP/WebSocket、会话发送线程和站点停止入口，不是全程序认证审计。路由使用的缓存、远端资源获取及底层 Java 实现未在本轮展开；不得把其未读行为写成已证。

| 入口或生产者 | 当前直接证据及持有物 | 必须覆盖的阻断点 |

| 两类 304 直写 | [缓存资源 304](<../common/src/main/java/github/gtouming/what_guys_doing/web/HttpConnection.java#L248-L264>)、[页面资源 304](<../common/src/main/java/github/gtouming/what_guys_doing/web/HttpConnection.java#L271-L288>)直接写头并刷新 | 第四、五处；无正文也必须走与资源类别匹配的输出路径 |
| 会话首包、队列及拆包发送 | [首包与出队](<../common/src/main/java/github/gtouming/what_guys_doing/core/Session.java#L74-L109>)先发 hello，随后锁内出队、锁外发送；[帧拆分](<../common/src/main/java/github/gtouming/what_guys_doing/core/Session.java#L112-L134>)分别发方块、实体和时间 | 出队后本地变量仍持有消息；一帧拆成多个发送，不能因第一个发送获准就豁免后续发送 |

| WebSocket 控制帧和关闭 | [接收控制帧](<../common/src/main/java/github/gtouming/what_guys_doing/web/WebSocketConnection.java#L135-L143>)调用[控制输出](<../common/src/main/java/github/gtouming/what_guys_doing/web/WebSocketConnection.java#L165-L175>)；[关闭](<../common/src/main/java/github/gtouming/what_guys_doing/web/WebSocketConnection.java#L79-L96>)先等同一锁、写 Close 帧并刷新，之后才关 socket | 控制帧本身不一定是世界数据，但刷新共享缓冲不能获得例外；故障出口不能复用会补写/刷新的关闭路径 |
| 停服及迟到接入 | [接收/派发/停止](<../common/src/main/java/github/gtouming/what_guys_doing/web/WebServer.java#L49-L71>)与[站点停止](<../common/src/main/java/github/gtouming/what_guys_doing/core/SessionHub.java#L233-L255>)没有在这些范围内建立接入登记屏障；[加会话](<../common/src/main/java/github/gtouming/what_guys_doing/core/SessionHub.java#L428-L439>)未核对运行状态 | 已 accept、未登记及已派发任务也须计入关闭集合；`shutdownNow` 不是连接全部关闭的证据 |

[会话启动](<../common/src/main/java/github/gtouming/what_guys_doing/core/Session.java#L38-L42>)未保存可等待的线程句柄；[会话关闭](<../common/src/main/java/github/gtouming/what_guys_doing/core/Session.java#L161-L168>)清队列后调用 WebSocket 关闭，没有建立发送者退出回执。结合上述锁顺序，只能指出潜在等待/残留，不能声称已经复现死锁或泄漏。

两个容易误读的边界：HTTP 的 try-with-resources 仅管理 socket，并未调用 `out.close`，不能宣称此处自动刷新了缓冲；本轮直证的是 WebSocket 关闭的显式刷新。另一个搜索命中 [AssetCache 的输出](<../common/src/main/java/github/gtouming/what_guys_doing/web/AssetCache.java#L250-L264>)是文件下载写盘，不是向观察者发送。实体静态包的[类路径读取与缓存](<../common/src/main/java/github/gtouming/what_guys_doing/web/HttpConnection.java#L318-L338>)也不能和瓦片/世界状态混称；不据此次入口表决定所有资源的公开资格。

## 三、具体候选：单一网络输出所有者

这是具体非阻塞通道／游标的后续工程审查对象；单一所有者与 R/B 语义已选，不表示该实现已采用。以非阻塞 `ServerSocketChannel`/`SocketChannel` 和 `Selector` 接管当前 socket 输出，不在旧 `BufferedOutputStream` 外再套一个检查。候选不引入框架依赖，固定部署 Java 及底层实现的实际契约仍须核对。

| 所有者 | 独占内容和允许动作 | 禁止的等待/旁路 |
| --- | --- | --- |
| 网络输出所有者 | 全部 HTTP 头/体、101 升级、WebSocket 数据/控制、每连接当前待写片段、就绪注册及关闭；一次连接内维持协议顺序 | 其他线程不持 socket/输出流，不直接 write/flush/close；网络线程不做磁盘保存或等待任务退出 |
| 游戏及管理受理侧 | 读取当前阻断；直接发布只收紧的服务／页限制，以既有有界所有权提交必要工作 | 不等发送锁，不调用网络 close/join，不把限制排在正文队列后；容量不足也能直接发布限制，不新建额外任务补位 |
| 必要缓存持久写者（仅在确有职责时） | 核定真实缓存来源、写者、发布及完成结果 | 不持网络锁，不直接恢复发送资格；旧写未知效果仍处理，不能因回调过时丢弃 |
| 正文准备所有者 | 在既有有界任务和内存账内准备不可变结果，携带运行／页／范围代和资源依据交接 | 无最终发送能力；计算完成不是获准发送；不把同步世界采样擅自搬到后台或新增无界线程池 |

### 状态发布与锁顺序

- 网络所有者的连接表、发送游标和选择器无跨线程写锁；跨所有者仅用有界交接和原子只收紧信号，不在任何交接锁中执行网络/磁盘 I/O，也不循环等待另一个所有者回执。准备任务拿不到容量就按既有出口处理，不旋转重试。
- 整站开通状态可候选为一个不可变状态描述的原子引用，绑定当前整站运行、故障变更版本及 enabled／本次就绪条件，而不是旧 Q154 每次人工开通请求。开放只能比较并交换所核对的那个完整状态；故障即使发生在已关闭期间也要使旧开放条件失效，不能重复使用旧对象或把版本绕回。字段、分配和最坏争用须在原预算内证明，不把此描述当已选格式。
- 服务／页／范围及真实资源限制同样必须使已准备结果失效；最终资格不是只看整站开关。细节状态用当前有效范围，合格迟到事实仍按已选事发范围规则处理，不能用“旧页代一律丢弃”重写普通范围变更政策。公开通用资源用自己的有效性和资源代，不凭身份路径猜测。
- 以上原子发布可以避免“迟到开通覆盖新故障”，但**不自动把原子状态检查与通道写入合并为一次原子操作**。这一剩余竞态见第六节。

### 一次发送的候选步骤

1. 接入句柄一旦取得即由网络所有者登记并计账，再决定处理或关闭；在受限状态下不能升级为观察连接。停服期间已取得的句柄不能丢在工作池队列里，登记/停止与新开通使用同一运行归属。
2. 正文准备者交付带资格依据的结果。网络所有者接纳时重核，形成“头片段、正文引用、各自偏移、运行／页／范围代和资源依据”的待写项；没有授权／登录字段，不复制一份免费正文，也不提前计为已发送。
3. 每次向通道写入前再检查当前限制和该项资格；处理优先的故障/撤销信号，受影响项不再进入下一次写。每连接最多一个正在输出的协议项，后续项仍在既有有界队列内，不能交错两份 HTTP 响应或 WebSocket 帧。
4. 非阻塞写返回正数时只推进实际报告的前缀；返回零则等下一次可写事件，不忙等；异常不得推断零提交，不重放不确定前缀。限制每轮尝试数和字节量可约束调度工作量，但具体值仍须按既定公平性/时延预算核定，不构成新预算。
5. 因故障、撤销或许可失效必须中止，且受影响项已输出部分协议内容时，丢弃应用侧剩余并直接关闭该连接，不补错误正文、另一帧、HTTP 结束块或 Close 握手来“凑完整”。已交操作系统的前缀不承诺收回；未交的后缀不能为了协议完整而续发。普通范围变更不能因此默认提升为全站故障，重连仍受原准入、次数、截止和峰值信用限制。

## 四、管理、故障与停止的顺序

1. 服务／页停止或真实必要依赖失效直接发布只收紧限制 R，立即拒绝受影响新准入和输出生产，不等磁盘或普通队列。来源不明的旧作用保留原所有权和成本。
2. 全站唯一一个 R 前已获准、总输入≤K的通道调用可返回；输出所有者下一写前处理限制、撤受影响可写安排、弃应用后缀并建立匹配 B。按真实依赖圈定影响页，不无依据清空不受影响页。
3. B 后核待发／必要引用清理及实际连接注销／关闭、相关生产者退出；这些与 B 分列。不建观察授权文件保存、旧登录失效或秘密交付；独立必要缓存若确需持久提交，另核写者、发布、保存顺序及退出。
4. 停止仅在必要的实际退出均有匹配证据后报告完成；超时、Future取消、空队列或 close 调用不证明退出。未知仍报未完成，游戏不等 I/O，迟到结果不能复活较旧代。
5. R20-Q163 已确认配置 enabled 且真正就绪时随正常服务器启动／重启自动公开，替代 Q154 每次人工开通；配置关闭、真实故障、残留未退出不能绕过。R21-Q166 已定故障消除／相关旧输出和写入已收束／重新就绪后有限重建当前，未知或耗尽保持关闭并提示管理员，不无限重试或回放；整站次数／时限／成本待工程核定，不套页级重连／压力探测数值。Q167 已定单纯墙钟回拨>5秒只告警，单调新鲜度／等待／重试／保留／峰值不延寿；其他真实一致性故障照处理。

Q155–Q156 保留的是 R/B 有界停止语义，不是观察授权保存事务。具体同步／调度、K、全入口迁移、固定平台及实际退出待证；第六节保留检查与提交间的真实窗口，不把后来 B 倒推为 R 时已经零提交。

## 五、字节、引用与有限退出怎么计

| 位置/结果 | 可以得出的结论 | 不能得出的结论 |
| --- | --- | --- |
| 正文已生成、排队或被发送者取到局部变量 | 仍是应用持有，按所属页/站点预算计账 | 出队、取得发送许可不等于进入操作系统 |
| HTTP/WebSocket 头、正文或缓冲只有一部分进入操作系统 | 仅已交前缀属于在途例外；后缀仍须阻断 | 不能因同一响应已开始就放行剩余内容 |
| 候选非阻塞写返回 `n > 0` | 按所依赖的写入契约记本次实际报告数量并推进游标 | 不证明字节在故障信号之前提交，也不证明浏览器收到/应用或采样新鲜 |
| 写返回零 | 保留待写引用，等待后续就绪 | 不能释放、刷新超时起点或当作成功 |
| 写抛异常、终止结果未知 | 不重放不确定前缀，关闭并记录未知结果 | 异常不证明本次提交零字节；关闭请求不证明物理执行已终结 |
| 部分数组/缓冲切片已发送 | 只要仍有引用，底层完整分配及其他副本继续计账；共享引用分别按逻辑账和物理账处理 | 移动游标、清队列或取消不能提前扣除仍保留的内存 |

已发送但必要应用确认尚未到达的依赖，继续按[既有未确认依赖与回收规则](<observation-delivery-engineering.md#L105-L134>)计账；实际写入不是 ACK。本候选没有确定最早实际发送时间的埋点，也没有证明完整内存、网络额度或采样时延。

非阻塞只用于避免为等待 socket 可写而主动阻塞，不证明固定 Java 实现的内部同步、native 调用、close 或 JVM 调度具有硬墙钟上界。工作量上限不等于调用退出时限。无法确认退出的通道、正文、回调和原生缓冲仍计账，观察保持关闭，tick 不替它们等待；既定峰值和回收目标仍须独立证明，不能允许永久挂账而宣布达标。

## 六、仍会失败的具体交错

令 F 为相关线程已获知故障并发布只收紧信号，W 为某些字节实际交给操作系统；这里只是推演记号，不是新领域术语。

```text
网络输出者：资格检查通过 ─────────────→ 调用通道写入 → W → 返回 n
故障线程：                 发布 F
```

若没有把最终资格裁决与提交字节联结的更强机制，`检查 < F < W` 仍可能发生。即使 F 在调用开始之前、线程只是刚好停在检查之后，也有同样反例；F 在一次未结束调用内出现时，同样不能由返回的 n 推断哪些字节早于 F。再次检查只能阻止下一次写，不能撤回本次已经提交的字节。

三种简单补丁都不足：

- **把检查与整个阻塞 write/flush 放进共享锁：**使封锁等在慢写后面；tick 若取得同一锁就等待 I/O，若只发原子信号则仍有上述窗口。不能据锁存在就宣布立即阻断。
- **使用非阻塞写：**缩小或改变等待方式，不自动保证“检查撤销状态并交操作系统”原子化，也不提供硬退出上界。本轮未核对固定平台底层实现，不能声称某个未审查的 API 已解决它。
- **把请求发布当成已完成屏障，或把已授权调用改名为此前在途：**若要求 F 时即零新提交，上述简单补丁仍不满足；不能悄悄把生效点推迟。后续 Q155–Q156 已明确接受输出所有者 B 及 R 后全站唯一一次≤K的残余，而不是称该残余为 R 前在途；因此保留反例但不再把该政策节点列为待选。

这是对所列候选及简单补丁的反例，**不是所有实现均不可能的结论**。第八节证明采用一个明确的输出所有者线性化点，可以把残余提交限制为一个有界写调用；Q155–Q156 已接受该可观察停止语义。工程仍须证明全部前提，不以政策接受冒充实现成立。

## 八、方案 1 专项评估：线性化语义已接受，工程待证

以下 `R`、`B`、`W`、`K` 仅是本节推演记号，不加入术语表：

- `R`：其他所有者以原子状态发布已校验的限制请求，并唤醒网络输出所有者；它不能排在普通正文队列后面。
- `B`：网络输出所有者处理匹配限制代次，禁止该范围后续写入、取消可写安排并丢弃应用后缀的线性化点；它在当次通道调用返回以后、下一次写入以前发生。
- `W`：一次通道调用向操作系统报告接纳的前缀；调用异常时，提交量保守视为未知。
- `K`：一次 `SocketChannel.write` 或 gathering-write 所见全部 `ByteBuffer.remaining()` 的总上限，HTTP/WebSocket 协议字节也计入；它不是正文、队列或 backing allocation 的上限。

### 能证明的残余提交包络

只有同时满足下列条件，才有 `R` 到 `B` 之间全站至多一次写调用、至多 `K` 应用协议字节的条件性结论：

1. 全站只有一个网络输出所有者，HTTP、101、WebSocket 数据/控制帧、关闭及所有已接受句柄没有旁路 `write`、`flush` 或补写式 `close`；未来若加入 TLS/代理内缓冲，也必须重新证明其提交所有权。
2. `R` 直接以单调限制代次发布并具有明确 release/acquire 可见性；`Selector.wakeup()` 只负责唤醒，不能代替状态可见性。限制槽不依赖可能被普通工作占满的队列，旧开通或回调不能覆盖它。
3. 一次资格检查只许可**一次**总输入不超过 `K` 的通道调用。禁止一次检查后的批量循环；调用返回后必须先重读限制状态，再处理其他连接、正文或控制帧。
4. 非阻塞调用同步返回其结果，且没有其他线程或库在后台继续提交同一应用缓冲。固定 JDK、操作系统和 provider 的这些契约仍须核对，不把接口名称当作证据。

最坏交错因而是：`检查通过 → R → 一次 write(W≤K 或结果未知≤K) → 返回 → B`。全站单一所有者使多个连接不会把它放大成 `N × K`；若改为每连接一名写者，或 `R` 只是排队命令，这个结论立即失效。正常返回 `n` 时只推进 `n`；异常按本次 `[0,K]` 未知提交处理，不重放。`R` 之前已交操作系统/代理、之后才抵达浏览器的旧前缀不受 `K` 限制，也不能被收回。

从 `B` 起可以证明网络所有者不再发起受影响应用层写入；部分 HTTP 响应或 WebSocket 帧直接断开，不补正文、结束块、Pong 或 Close。停止完成还必须独立核必要引用、连接实际注销／关闭与相关生产者退出；`B` 自身不是实际收束。只有另有真实必要持久职责时才核相应保存顺序，不建立观察授权文件或旧登录失效步骤。

### 不能由该包络证明的事项

- `R` 到 `B` 没有硬墙钟上界：`K` 限制本次输入量，不限制 JVM 调度、native 调用或关闭完成时间。没有 B 回执就保持观察关闭、管理未完成，但 Minecraft tick 不等待。
- 既有 `32 Mbit/s` 一秒突发是滚动传输信用，不是单次写量子，不能反推 `K`。按应用字节跑满它至少需要 `ceil(4,000,000 / K)` 次足额正写每秒；零写、部分写和协议开销只会增加调用。`K` 的安全残余与调用开销须在后续一轮取舍，并经固定平台实测。
- `K` 不替代每页 `4 MiB`、全站 `32 MiB` 待发/额外未确认包络，也不释放被切片引用的完整 backing allocation。被取消或结果未知的对象，在任务、引用或句柄仍实际持有时继续计账；输出隔离不释放这些成本，回收还须分别核实任务退出及实际持有结束。
- 非阻塞、单一线程、收到命令、空队列或 `close()` 返回都不能单独证明硬退出、物理回收、浏览器收取结果或跨重启可信收束。

### 与既有决定的适配

旧 Q67 的 `R → B → 授权保存` 仅作历史追溯。公开路径保留 Q155／Q156 的停止语义：R 直接发布单调限制，一个此前获准、输入≤K的调用可返回，下一次写前建立 B；不把 R 后字节谎称为此前已提交。没有观察授权保存步骤，实际必要缓存持久职责另核。

Q157 的授权／PUBLIC 树仅留历史；R20-Q165 的活动页等份与普通公开 HTTP 单一有限桶已确认。因此**发送生效点与匿名公平政策已接受**，但不能写成具体调度或实现已通过。唯一实际所有者、全入口迁移、直接可见限制、通道切片、固定平台与退出／成本证据仍待核定，`K` 没有选值。

## 九、当前 HTTP 输出清单与切片边界

本节穷举当前 `HttpConnection` 可产生的状态：`101`、`200`、`202`、`204`、`304`、`400`、`404`、`405`、`503`，另有请求行非法、单行超限或 I/O 异常后的静默断连。旧 Q53 未认证世界拒绝已由 Q162 替代：只公开已定义观察路由及资源，不公开任意文件、配置或敏感诊断；不需要观察登录。当前 Origin／方法／路由与有限输入仍须核定，`Upgrade: websocket` 在普通方法／路径校验前进入升级分支不能被公开策略合理化。

| --- | --- | --- | --- |

## 十、当前 WebSocket 输出公式与应用分批

令 `V(x)` 为 `varUInt` 长度（1–5 B）、`B` 为 UTF-8 字节数、`L` 为应用载荷。当前每次 `sendBinary` 产生一个未掩码、`FIN=1` 的单一二进制帧，帧总长是 `L+2/4/10`；帧头、载荷 write 和 TCP 分段都不是同一边界。候选可保持一个逻辑 WebSocket 消息，把其编码后的连续帧字节流以游标分成多个至多 `K` 的**通道写入**；这不要求改变为多个 WebSocket 消息，也不把 `K` 解释为 RFC 6455 分片尺寸。

| 应用消息 | 当前载荷公式或上界 | 必须补齐的生产边界 |
| --- | --- | --- |
| HELLO | `L=13+Σ(9+V(Bᵢ)+Bᵢ)` | 维度数、维度 ID 字段宽度与名称总字节当前未统一封顶；编码循环不会因 `u16/u8` 字段自动截断 |
| SECTION_FULL | `L=4625+4P+512b`，当前 `P≤4096`，`b=0`（`P=1`）否则 `ceil(log2 P)`，故 `L≤27,153 B`；完整 WS 帧最大 27,157 B | 当前唯一生产路径已有静态消息上界；仍按同一帧字节流跨多个 `K` 写，不能由此反推 `K` |
| BLOCK_DELTA_BATCH | 输出 `N` 条时 `L=7+17N` | `N` 只写入 `u16`，编码仍遍历全部记录；收集器无总量 cap，须在可独立验证的记录边界分批或拒绝/降级，不能仅截断计数字段 |
| ENTITY_SNAPSHOT | `L=9+ΣV(removedId)+Σrecord`；全字段记录为 `V(id)+85+V(vehicle)+V(item)+V(B)+B` | current/removed 写 `u16` 但配置及累计未钳位，自定义名无本地字节上限；须按独立实体记录续批，并给名称及计数字段硬界 |
| TIME_SYNC / CHUNK_UNLOAD / 应用 PONG | 分别 13/10/1 B；unload 当前无调用方 | 尺寸已有界；客户端 ping 触发的应用 PONG 仍须受入站限额与公平调度，不能形成旁路 |
| WS 控制 Pong / Close | 控制载荷至多125 B；当前发送的空Close完整帧为2 B、载荷为0 B | 控制帧、raw close和任何flush均须归唯一所有者；当前 `close()` 仍尝试写Close，不是故障raw-close实现 |

单个 `TickFrame` 当前最多依次产生 block/entity/time 三条，另有每 tick、每会话至多配置值 `S=max(0,maxSectionsPerTick)` 个 section；默认 `S=2`，但配置未钳制，客户端 ping 产生的 PONG 也不在该条数内。旧队列按“条”而非字节限制，因此不满足既有内存包络。传输层按 `K` 切片只控制一次 `SocketChannel.write`／gathering-write 的总输入，不保证底层 native syscall 次数；HELLO、block delta、entity、HTTP 大对象仍必须在生产端具备硬上限或可独立确认/失效的应用分批，才能证明 4 MiB/页和 32 MiB/站点包络及确认依赖。

## 十一、有界公平的单一所有者调度候选

1. **限制优先且不排普通队列。**每轮开始先 acquire 最新单调限制代并处理全部安全信号；每次 write 前重读，调用返回 `n>0`、`0` 或异常后的第一动作也重读。命中 `R` 就撤受影响 `OP_WRITE`、丢后缀并建立匹配 `B`，再做任何普通工作。一次资格检查只许可一个总 `remaining≤K` 的调用。
2. **连接工作量须重新分类。**已 accept 句柄立即计入生命周期槽；旧 `U32+H16+P8+Q8≤64` 是身份方案的条件算术，不是现行64连接许可。[P0连接／描述符候选](<observation-production-capacity.md#L141-L142>)另列所有accepted／握手／活动／idle／closing／旧连接合计32、工作描述符64；不是已核定配置，普通HTTP并发16仍是已有上限。转换先取得目的容量、全程无未计账窗口；错误响应也不另建免费池。`accept≤1`、每ready连接 `read≤1`、每阶段每页 `write≤1` 仅为有限机会候选，不是墙钟上界，也不替代完整输入限额。
3. **匿名公平边界已按R20-Q165／R22-Q170确认。**原授权→页→连接及PUBLIC虚拟授权树仅历史。每活动页权重1、普通公开HTTP单一总桶权重0.5，共享总预算；同页多连接不加份额，全站active≤8，满额拒新不踢合格旧页；不识别账号／IP／指纹，同人可多页，旧身份额度不复活、不扩容。控制及错误响应不得绕过字节、调用机会和资源预算；定义路由以Q162为准，具体归桶交接及页内游标仍是工程候选。
4. **类别与最迟机会。**页内沿用Q101严格类别顺序，但协议控制优先只在合法的新帧／响应边界选择，不把≤K通道切片当作插入边界；R/B限制处理优先不等于免费发送Pong／Close。从既有15/45/60秒构建时限、0.5/2秒待发年龄、1/5秒依赖年龄计算最迟服务机会，给必要近景保留进展而不另造固定份额；不足则按既定降级、缺口或暂停出口处理。
5. **零写、部分写与协议原子性。**`write=0` 消耗所属页／HTTP总桶本阶段机会，不扣字节、不推进游标、不续滞留或ACK年龄；连接当场退出本次可服务快照，换同桶另一连接不退还机会。旧level-ready、普通wakeup、重建快照或开新轮不能单独授权立即重试，须等待有效可写条件或原截止导出的有界重试；具体注册策略待平台证据。partial只扣／推进实际 `n`，下次先检查限制和资格；同连接不交错两个HTTP响应或两个WS帧，异常按 `[0,K]` 未知、不重放。
6. **包络与退出。**大对象在可独立验证边界分批生产；若单一不可拆生产对象本身不能进入既有 4 MiB/32 MiB 包络，就拒绝或暂停，不借 `K` 扩容。失效时仍持有的 backing allocation、队列项和通道继续计账至实际持有结束；隔离只撤发送能力，不等于释放引用、句柄退出或物理回收。75% 持续 1 秒的降级、硬上限立即处置、确认/滞留年龄及显式缺口规则不变。

第十七节补入归桶交接、有限阶段成员与持久游标的必要条件；每轮有限机会不证明无饥饿、稳定性能或硬墙钟退出。已选的是Q165／Q170竞争偏好和R/B语义，低层循环尚未通过；不自行选择selector timeout、缓冲向量数、零写重注册毫秒数或K，不把工程候选伪装成新的产品预算。

## 十二、`K` 的静态代价与当前决策准备度

`K` 只改变 `R→B` 期间最多新提交字节和完成同一协议字节流所需的 write 调用下界。按纯算术，32 Mbit/s 即 4,000,000 B/s，4/16/64 KiB 分别至少需要 977/245/62 次足额正写每秒；80 Mbit/s 即 10,000,000 B/s，分别至少需要 2,442/611/153 次。零写、partial、协议字节、公平切换和 selector 开销只会增加调用数。最大 section 帧在三者下至少需 7/2/1 次足额调用；2,959,607 B entity bundle 至少需 723/181/46 次。以上只是算术下界，不是吞吐、CPU 或时延证据。

静态工作已经排除了“`K` 必须容纳一个完整 HTTP 正文或 WebSocket 应用消息”的前提：消息可保留逻辑身份并跨多个有界写。因此无界消息不会直接强迫选择大 `K`，但会阻断生产/内存证明。反过来，静态代码、既有速率目标、8 KiB 旧缓冲、32 Mbit/s 突发或 27,157 B section 帧都不能证明 4、16、64 KiB 中哪一个能同时满足安全残余、CPU、延迟及吞吐。

`K` 的推荐值由固定代码、平台契约和经另行授权的正写／零写／partial、吞吐、CPU及分位时延证据核定，不要求用户猜参数，也不把数学下界当性能通过。若证据揭示既有残余或性能承诺冲突，再只向用户提出真实行为取舍。本稿 Q157 的真实授权／PUBLIC公平树及其“政策已通过”评级仅属于旧身份方案；现行匿名页面公平已由 R20-Q165 明确确认，具体游标／调度、协议、K 与完整容量不因此通过。当前没有运行测量许可，不能为选 K 自动启动夹具或恢复 V1 实验。

## 十四、K 的起始评估候选，不是默认值

**工程建议，未选择、未测量：**先把 `K_start=16 KiB=16,384 B` 作为纸面比较和未来最小申请卡的起始候选；保留 4／64 KiB 对照，不把它写入产品配置，也不称为安全—性能推荐值。理由仅是两端之间的明确代价：相对 4 KiB，单次残余输入许可增至 4 倍，足额调用数下界约为四分之一；相对 64 KiB，残余许可为四分之一，调用下界约为 4 倍。整数取整会改变精确比值。

| 80 Mbit/s，10,000,000 B/s 的足额调用下界／秒 | 2,442 | 611 | 153 |

各值为 `ceil(bytes/K)`，不是实测吞吐、CPU、调用时长、分位时延或零／部分写代价。历史 bundle 只用于传输算术，不获得生产许可；[有限实体消息候选](<observation-production-capacity.md#L109-L158>)另受完整生产及分批合同约束。一次输入包括全部 HTTP／WS 头和本次 gathering 各 buffer 的 remaining 总和，不能按每个 buffer 各给一个 K。

最终 K 仍须同时具备：下节的固定平台证据、全入口唯一实际输出所有者及 R／B 证明、生产／临时 direct／历史 backing 容量闭合，以及另行批准的正写／零写／部分写／异常、吞吐／CPU／时延和退出证据。一次调用输入有限不推出 native syscall 次数、物理驻留或硬墙钟退出有限；16 KiB 候选没有关闭这些缺口，不要求用户猜 K，也不恢复 V1 或授权 V2。

## 十六、普通 HTTP 半页权重与有限轮转候选

R20-Q165 已选择活动页等份轮转、同页多连接不加份额，以及普通公开 HTTP 共一个有限桶；**R22-Q170 已确认每页权重 1、普通 HTTP 总桶权重 `w=0.5`（半页）**。`w=1`（整页）仅保留为未选比较方案；优先实时观察，接受普通下载在页持续竞争时获得较少服务机会的代价。这是竞争偏好，不是认证、额外预算或下载完成时间承诺；低层算法和计量合同仍未核定。

令 `p` 为持续合格、有积压且可服务的页数，每页权重 1；HTTP 桶可服务且有积压时 `h=1`，否则 `h=0`。`D=p+h×w`；`D>0` 时，理想稳定份额为单页 `1/D`、全部页 `p/D`、HTTP 总桶 `h×w/D`。`D=0` 时没有服务，不做除法；空闲桶跳过且不攒信用，只有 HTTP 可服务时可使用现有全站预算，半页权重不是无条件 50% 上限。

| 可服务页数 | HTTP 状态 | w | 单页 | 全部页 | HTTP 总桶 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 4 | 有积压 | 1 | 20% | 80% | 20% |
| 4 | 有积压 | 0.5 | 22.22% | 88.89% | 11.11% |
| 8 | 有积压 | 1 | 11.11% | 88.89% | 11.11% |
| 8 | 有积压 | 0.5 | 11.76% | 94.12% | 5.88% |
| 4 | 空闲 | 两者 | 25% | 100% | 0 |
| 8 | 空闲 | 两者 | 12.5% | 100% | 0 |

**必须声明计量对象，不能同时许诺两种公平。**机会轮转候选在 `w=1` 时每轮每个可服务页与 HTTP 桶至多一次调用；`w=0.5` 时跨两轮每页两次、HTTP 一次，分散安排而非一次完成大对象。每次机会只允许一个总 remaining≤K 的 write／gathering 调用，并受全站实际字节、调用及资源限额约束。表格在此版本表示机会比例，不是实际带宽：设各桶调用数为 `C_i`、正常正写实际字节 `B_i=Σn`、平均返回 `n̄_i=B_i/C_i`；有正常正写字节的观察窗口中，单页实际比例为 `B_i/(Σ页 B_j+B_HTTP)`。只有持续可服务、完整轮转实现各页相同调用数且 HTTP 调用数为其 w 倍时，才能改写为 `n̄_i/(Σ页 n̄_j+w×n̄_HTTP)`；进一步各桶平均实际 n 相等且为正时，才等于表中比例。零写也消耗机会，输入 K 不等于返回 K。

若选择实际字节服务账候选，则以最小归一化服务量 `v_i` 选可服务桶，正常正写后 `v_i←v_i+n/w_i`；空闲转有积压时加入当前服务基线，不继承空闲信用。此版本按实际 n 而非输入 K 计量，零／小部分写可能需要更多调用，不能再保证固定调用比例。上述公式只是持续需求／可服务且没有不计账优先旁路时的稳定比较；任何版本均不保证任意短窗口比例、最低速率、完成时间或浏览器已应用。异常是未知接受前缀 `[0,K]`，按本次预留额度保守处理并单列未知，不记成零字节成功或重放。具体算法、游标与注册策略仍是工程候选，不让用户猜这些实现参数。

同页 `c` 个连接共用该页权重；HTTP 的 `m≤16` 个响应共用一个 w，不是 `16w`。仅在桶内也等机会轮转时，各响应的理想机会为 HTTP 总桶份额／m；例如四页、w=0.5、m=16 时为 `1/144`，不承诺等字节或等完成时间。[每 HTTP 两个 16 KiB 工作块](<observation-production-capacity.md#L141>)是生产／资源候选，不是 K、外层权重或一次 32 KiB 写许可；若 gathering 同时引用它们，本次 remaining 总和仍≤K。

有限收束规则沿用第十一节，不借竞争扩预算或延寿：

1. 调用前及返回后的第一动作重新观察限制；R 后至多一个此前获准、总输入≤K 的全站调用返回，匹配 B 必须先于下一写。部分 HTTP／WS 对象不能要求补后缀、终止块、Pong 或 Close；raw-close，实际残留继续计账至持有结束。
2. `n=0` 消耗所属页／HTTP总桶本阶段机会，不扣字节、不推进游标、不刷新进度或年龄；立即退出本次可服务快照，换同桶连接不退还机会。旧level-ready、selectNow、普通wakeup或新轮本身均不是立即重试许可；须等待有效可写条件或原截止导出的有界重试，准确注册策略仍待平台证据，不编造毫秒数。
3. 部分写只按正常返回的实际n扣费、推进原游标并保留响应／帧身份；下次先复核限制和资格。同连接不交错两个HTTP响应或两个WS帧，未完FIN帧的≤K通道切片不是Pong／Close插入边界；其他连接／桶仍可轮转，不在内层循环强行写完。
4. HTTP头／101／错误、WS数据／控制全部纳入同一所有者与预算；第十七节已给出未采纳输出归HTTP总桶、采纳后WS输出归页桶的交接候选。同页资源请求仍归HTTP总桶，没有第三个免费控制桶；入口迁移、生命周期协议和实际采纳仍待证明。
5. 原 15／45／60 秒构建总时限、0.5／2 秒待发年龄、1／5 秒必要依赖年龄、严格类别顺序及压力／缺口／暂停出口不变。HTTP 竞争、零／部分写都不延寿；不能同时满足原合同就按既定出口处置，不补造普通 HTTP 的应用 ACK 或套用页专属超时。

本节只有静态比较与有限规则，没有运行通过。R22-Q170 已确认 HTTP 总桶半页权重，只决定相对竞争偏好；低层算法及计量仍待核定，不因此选择 K、证明 selector／native／退出、扩大容量或授权实验，也不重新打开已撤回的凭证分支。

## 十七、输出归桶交接与有限阶段的必要条件

本节是上一节的工程补充，不新增政策问题、预算、领域术语或ADR。已核对当前源码顺序及纸面反例；所有者迁移、生命周期协议、低层计量和平台行为仍未实现或通过。

### 17.1 当前顺序与归桶交接候选

[HTTP升级](<../common/src/main/java/github/gtouming/what_guys_doing/web/HttpConnection.java#L37-L89>)先 `out.write`、`out.flush`，正常返回后才进入WS；这些void操作未记录实际n。升级仍在普通方法／路径校验前，不能由公开策略合理化。WS随后[注册连接、启动Session线程并读消息](<../common/src/main/java/github/gtouming/what_guys_doing/web/WebSocketConnection.java#L33-L52>)；[HELLO](<../common/src/main/java/github/gtouming/what_guys_doing/core/Session.java#L38-L80>)仅先于同一发送线程的队列输出，不保证早于读线程的[Ping→Pong或Close回应](<../common/src/main/java/github/gtouming/what_guys_doing/web/WebSocketConnection.java#L135-L143>)。[addSession](<../common/src/main/java/github/gtouming/what_guys_doing/core/SessionHub.java#L428-L440>)只有按连接创建／登记，不是当前页采纳、同页去加权或全站唯一输出所有权。

| 输出阶段 | 唯一归属候选 | 交接与失败边界 |
| --- | --- | --- |
| 普通HTTP、HEAD／304／固定错误、拒绝以及101 | 普通公开HTTP总桶，权重0.5；同一页发起的资源下载也不转入页桶 | 请求、响应、句柄、描述符和实际backing先占既有容量；没有免费错误桶 |
| 101未全部正常推进，或尚无当前页采纳提交 | 仍保留HTTP总桶归属；若未来允许额外采纳前WS控制，其输出也不得获得免费桶，但当前候选不在采纳前发送WS字节 | 先取得目的页／连接／任务容量，再由唯一所有者复核enabled、就绪、限制及精确当前生命周期；整个101按实际n完成后，一次提交归属，提交前挡住HELLO及读线程控制输出 |
| 已由唯一所有者采纳的当前页WS输出 | HELLO、应用PONG、WS Pong／正常Close及数据共同使用该页权重1；同页多连接共一份 | 控制优先仅在合法新帧边界，不增加权重、全局信用或资源；采纳提交不证明浏览器已应用或活动页已实时就绪 |
| 页失效、隐藏、停止或旧连接尚未退出 | 受影响的旧连接／页代没有新发送机会；相关旧对象仍归原生命周期和真实资源账，不据此停止不相关合格页 | 不转成HTTP免费尾写，不补旧帧／Pong／Close；匹配B、raw-close及实际退出分别核对 |

101全部正常推进只是必要条件，不自动授予页资格；目的容量预留也不授予采样或发送权。生命周期标识只用于相关性，不是凭证。源／目的归属和容量转移须由同一所有者一次提交，无空档或双份机会；服务／页R发生时先建立匹配B，取消交接。页面创建、活动资格、重连保留及对应协议字段仍待最终方案核定，不凭连接数或 `addSession` 填补。未来采纳前置不能依赖被挡住的HELLO／Pong或其应用回执；采纳前入站仅可有界解析并提交候选，不获得采样／输出权。[当前浏览器](<../common/src/main/resources/assets/what_guys_doing/web/app.js#L2114-L2127>)在onopen即发订阅和应用Ping，不等HELLO；这不证明未来协议已经完整，也不能断言现源码已形成启动循环。

若101已经部分输出，或异常使接纳前缀未知，就不能追加第二条HTTP错误状态行：它会接在残缺升级头后，或成为已经升级的流内非WS字节；只能按未知提交保守计账并raw-close。当前HTTP IOException路径只记日志并关闭socket，没有补错误，但[WS close](<../common/src/main/java/github/gtouming/what_guys_doing/web/WebSocketConnection.java#L79-L96>)仍尝试发送空Close；读线程回应Close不置 `open=false`，后续清理还可能再发Close。[应用C_PING](<../common/src/main/java/github/gtouming/what_guys_doing/core/Session.java#L136-L169>)经普通队列入应用PONG，不等于新的控制额度。以上不证明现有WS已满足部分对象raw-close合同。

### 17.2 两阶段机会候选与计数范围

仅为实现weight1:0.5提供一个待确认的机会算法候选：竞争阶段各枚举至多8个页桶、每桶至多一次调用；两个阶段分散安排一个HTTP总桶机会。每次调用仍先复核限制、资格及全局信用，全部remaining≤K。不强行用完机会，不在机会内循环写完整对象。

设两个阶段的有限页成员集合为S1、S2，HTTP竞争机会是否使用为a∈{0,1}，此**竞争枚举段**调用上界是 `|S1|+|S2|+a≤17`；只有成员稳定且始终可服务的同一p页，完整两阶段实际获得每页两次、HTTP一次机会时，才是 `2p+1` 的机会比较。active≤8只界同时存在的页，不界阶段内不停退旧接新的累计页数；阶段集合不能被新忙／重连／代转换不断扩写，新成员只能在后续合法阶段加入而不攒旧机会。

页级已耗机会、阶段进度及未访问游标须跨普通wakeup、信用不足和短暂停止保留；同页换连接、旧代回调或重建快照不能重置它们。反例：每次预算用尽后从首项重开，即使“每阶段至多一次”，前页仍可能反复被服务而后页永久轮不到。因此有限次数不是无饥饿证明；还须核定有限成员扫描、资格变化、截止出口及平台调度的活性。

无页具有合格、积压且可写的需求时，HTTP可消耗既有全局预算；页本阶段机会已耗或枚举结束，不等于无页可服务，不据此转入独占段。独占服务另行计数，不能把额外调用夹入竞争枚举后仍称整段≤17；恢复竞争不携带闲时信用，HTTP竞争机会状态不能被独占模式切换返还。普通事件或新轮也不自动解除零写等待。任意短窗口可能只有HTTP一次正写，故不保证窗口比例；八页各两次返回n=1、HTTP一次返回n=K时，HTTP实际字节比例为 `K/(K+16)`，不是1/17。

`n=0` 已消耗桶级机会，连接撤出本次可服务集合，不能换同桶的另一连接补写；有效可写／有界重试条件待固定平台核定。若改用最小归一化实际服务账，零写使v不变，立即重选同桶可忙旋；仍须有独立调用机会及等待门，不伪扣ε字节、不续原截止。这两个算法仍是替代候选，不能同时承诺固定调用比例和实际字节比例。

### 17.3 三类账与有限失败出口

| 调用结果／事件 | 机会账 | 实际字节／未知提交账 | 真实资源与生命周期账 |
| --- | --- | --- | --- |
| n=0 | 所属桶本阶段机会已耗，不因换连接返还 | 正常返回字节0；不推进任何游标／进度／年龄 | 原backing、句柄、元数据和等待仍持有，不清零 |
| 正常partial | 一次机会已耗；下次重新复核 | 只按实际n扣信用／推进原游标，保持响应／帧身份 | 完整底层分配按真实持有继续计，不能只算剩余切片 |
| 异常 | 本次机会已耗，不立即重放 | 接纳前缀在本次预留范围内未知，包络≤K；保守占账，单列未知 | raw-close或隔离后仍须实际退出和最后持有结束，不把异常当0成功 |
| R/B、丢队列或close请求 | 停止受影响的新机会；不建立免费尾写桶 | B不撤回此前OS／代理已接纳字节 | 输出隔离、句柄注销、生产者／回调退出、最后持有及物理回收分列取证 |

HTTP并发16已满时，不能先构造第17个503再称它很小：错误响应也须取得已有响应槽、描述符和backing预算；无容量则按既定拒收／关闭出口，不新建错误／closing池。P0提出的32连接、64工作描述符、每页256描述符及非页HTTP／控制8 MiB仍是未选的生产候选；既已确认的每页4 MiB／全站32 MiB交付包络不因此变成待选或额外预算。数量、字节及实际持有须同时核定，不能用剩余字节替代缺槽，也不把关闭调用当槽已归还。

17调用、有限扫描／关闭次数和输入≤K都不是native调用次数或硬墙钟界；全部仍受原构建、待发、依赖、压力／缺口／暂停及峰值截止约束，不给普通HTTP造应用ACK或页专属超时。本补充不新增须用户猜的参数，也不选择K、完整生产P0或低层算法；平台、旧作用退出和双加载器最终转换仍待独立证据，不授权实施或实验。
