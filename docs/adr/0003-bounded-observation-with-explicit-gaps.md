# 状态可合并，交互信息缺失必须可辨识

中间位置和姿态状态允许合并，但已承诺展示的交互信息不能静默吞掉并解释为没有发生；丢弃、断流等不完整须显式表现为观察缺口，恢复后重新建立当前状态。缓存保持有界，不以无限保留或阻塞游戏等待慢观察者换取可靠性，而以可辨识的缺口保住服务器运行和有限资源稳定。合格常规负载仍须满足已选零漏收目标，不能以标记缺口冒充验收通过；达到待发包络时先安全合并可替代的未交付状态并舍弃可选细节，仍必须丢事实则明确缺口并暂停相关页，优先隔离慢页，不另开无界积压。首批事实、保留、待发包络及溢出出口见 [设计记录](<../observation-design.md>) R9-Q75、R10-Q94 至 Q95、Q113、Q121、R11-Q128。R12-Q140 至 Q141 已选择浏览端解析并应用成功后的有界累计确认，不把 socket 写成功当作基线已应用，也不等待 GPU 或动画；只在有证据时标明缺口起止和数量，未知明确，当前恢复不补历史。R13-Q148 至 Q149 已选累计确认节奏与无确认出口，并将等待确认而额外保留的载荷、基线依赖和引用计入既有待发字节包络，避免用已写出作为不计账理由；已确认当前状态仍受总内存预算约束。最小安全依赖闭包及共享引用计账仍须工程核定，应用确认不引入事实重发历史。
