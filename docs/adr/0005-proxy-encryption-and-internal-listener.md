# 反向代理负责加密入口，内置端口允许显式对外绑定

**现行公开模式：** [ADR-0011](<0011-public-read-only-observation.md>)取消观察认证、登录和 Cookie 身份门；R20-Q164 允许内置数据端口显式对外绑定，不强制回环。R21-Q168 已选择由运营者配置的反向代理负责 HTTPS/WSS 和证书，模组不内置证书管理或自动申领；接受额外代理部署工作以缩小模组职责，保留网页、数据及 WebSocket 同源和非嵌入边界。代理不建立观察者身份，显式外绑能力不取消；具体代理产品、配置、证书来源与实际部署仍待核定，见[现行公开访问合同](<../observation-public-access.md>)，本决定不授权监听或部署。

## 原部署与认证组合（历史；与现行修订冲突部分不再适用）

观察站点由反向代理提供 HTTPS 和加密 WebSocket，模组服务默认监听回环地址，容器等场景须显式配置受控内网地址，不直接暴露内置明文端口。相比在模组内管理证书与加密连接，选择额外的代理部署环节以控制模组职责和默认暴露面，并满足 WebGPU 的安全上下文要求。此决定不自动授予转发身份头可信性，认证与撤销由模组负责，见 [ADR-0006](<0006-module-owned-observer-authentication.md>)。首版页面、登录、数据和加密 WebSocket 使用同源入口，不支持跨站前后端或第三方嵌入；相比允许任意部署组合，接受这项限制以减少认证与代理配置的组合。登录采用受保护的主机限定 Cookie，变更请求和 WebSocket 严格校验预配置的同源入口，细节见 [设计记录](<../observation-design.md#L124>) R8-Q61；不为了跨站兼容放宽来源或秘密保管边界。
