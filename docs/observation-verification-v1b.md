## 执行顺序与上限

仅使用已核对的 [Java](<E:/Java/21/bin/java.exe>) 和 [Javac](<E:/Java/21/bin/javac.exe>)；不运行 Gradle、现有项目脚本、测试套件、模组或游戏类。编译仅本次源码和 JDK，`--release 21`、`-proc:none`、`-Xlint:all`，不加载注解处理器或外部依赖。执行前复核可执行指纹及 Java 启动选项存在性；出现未经列明的注入选项就停止，不打印其内容或修改全局环境。

按下列顺序，一步通过才进入下一步；**自建子进程至多启动 3 次，每步至多 1 次，不自动重试**：

1. **启动门**：一个自建 JVM 只输出固定 ASCII ready 标记并正常退出；不写世界/授权数据。沿用 Java ProcessBuilder 的 stdin PIPE、stdout PIPE、stderr 本次普通文件，无继承终端、命名管道、替代重定向或其他 shell 执行子进程。必须同时取得完整标记和正常退出。出现 CreatePipe/访问拒绝，整批立即停止，不进入后两步。
2. **正常完成对照**：新夹具中的旧合成 JSON，经同目录 pending 文件写入前缀、`force(true)`、ready、父进程通过既有 stdin 匿名管道给一个固定完成指令后，写完固定新 JSON，再 force、`ATOMIC_MOVE + REPLACE_EXISTING`。断言完整新字节和正常退出；无非原子 fallback。此步证明指定合成路径确实能走到替换，不是生产存储实现。
3. **一个中断点**：另一新夹具运行同一写路径，在收到“前缀已 force、尚未替换”的 ready 后，只调用该次返回的 Process 对象的 `destroyForcibly()`，有界确认退出，再断言 current 为固定旧字节、pending 为固定前缀。没有完成指令、没有任意时点/大量循环、没有搜索或终止既有进程。若自然退出、握手不完整或不能确认终止，该步失败而非中断通过。

资源界限：顺序运行，一次仅 1 个顶层验证任务，同时至多 2 个本次 JVM；父 JVM 最大堆 256 MiB、worker 128 MiB，总最大堆 384 MiB。每个顶层命令受管理运行上限 120 秒，不使用无超时后台命令。就绪等待最多 10 秒；worker 未收到完成指令最多等待 10 秒并退出失败，不无限等输入；终止确认最多 5 秒；读端后处理最多等待 1 秒。每个顶层验证任务的各等待阶段共用单调时钟截止，不叠加等待续期；验证程序每任务目标总截止 40 秒。必须先终止/确认本次 worker，再处理读端，禁止在终止前同步关闭可能持锁的 reader。读端不能退出或 worker 清理未确认则记录失败、停止，不运行后例；不能声称这是 OS 不可取消 I/O 的硬保证。

单个合成 JSON ≤ 2 MiB；本次生成文件总量 ≤ 16 MiB，文本及原始日志总量 ≤ 2 MiB。仅记录固定合成字段、源指纹、任务/PID/终止请求及退出证据，不用实际凭证。无清理/删除必需步骤，默认保留小型证据。输出或临时文件要求越界时停止。
