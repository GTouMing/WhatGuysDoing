## 第一项静态工程工作：依赖、失效与计账

### 必须说明的关系

1. **内部共享不等于对外并集**：共享采样可被多页使用，但每页发送和事发范围过滤独立。不能向所有页发送并集，再让浏览端隐藏；某页越权不能借共享引用进入另一页可见输出。
2. **生命周期不能合并**：服务器运行、连续实体活动、页观察及其当前构建/应用状态须可分别失效；玩家 UUID、数值 ID 或已写 socket 都不替代它们。公开模式没有共享登录生命周期。
3. **先确定真实依赖，再决定局部边界**：标明某个结果是否依赖基线、类型/状态解释、坐标、活动身份、所属范围及此前应用结果。只使真正受影响的集合失效；不能无依据假定“单块失败只影响单块”，也不能用一律停全站掩盖缺少依赖核定。
4. **失效在释放之前**：若仍必要的依赖因包络、取消或失败必须回收，先停止相关流水并使旧代无效；之后才断开队列/任务/引用。已发未确认的数据不能跨失效边界继续作为增量基线；迟到完成结果不能重新启用旧代。
5. **预算跟随实际保留**：待发载荷、未确认载荷/基线及额外引用共用每页 4 MiB、全站 32 MiB；仍需的当前状态另计总内存。共享对象的每页归属、全站物理计数及引用/编码开销必须单列，不能没有任何页认领，也不能重复释放。共享底层全站物理只计一次，各依赖页按完整保留量归属，不均摊；对象／容器容量、实际引用与回收测量仍须核定。
6. **取消请求不等于回收完成**：在真实工作、回调或 I/O 仍持有对象时继续计账；新尝试、手动重试、范围切换不重置既有峰值、流量信用或截止。不能用取消 Future、空队列或 socket 写成功宣称资源已释放。
7. **确认与采样分别成立**：确认只证明特定有效数据已解析并应用，刷新采样才证明世界信息新鲜。重复/旧代/部分确认不延长未覆盖依赖年龄；必要近景“可用或可信进展”不能被缩成必须完整或稀疏两次成功。

这些关系约束候选方案，不规定序列号字段、线上协议或线程/锁实现。现已对照实际代码形成[依赖闭包与对象计账候选](<observation-delivery-engineering.md>)；具体应用提交、确认表达、完整开销及同步边界仍未核定，不把图表形成标成完整工程通过。

### 先用具体场景检查候选方案

| 场景 | 静态审查必须给出的回答 |
| --- | --- |
| A、B 两页内部共享采样，A 的未确认依赖超时 | 列明受影响输出及引用；A 失效不自动停止无该依赖的 B，但 B 若实际依赖失败对象也不能继续增量；A 释放不提前释放 B 仍需对象 |
| 页已切换范围，旧构建随后完成 | 旧范围数据不能进入新页状态或续采样新鲜度；完成回调丢弃数据之前，其占用仍计入原尝试及峰值 |
| 部分 ACK 不断到达，最早必要依赖始终未覆盖 | 原发送时间继续计龄，正常 1 秒/固定慢网 5 秒或更早硬限制触发；不能每收到一条 ACK 就重置全页计时 |
| 完全压力暂停时仍有取消中的任务 | 释放活动名额不赋予候选采样权，也不免除残留成本；新探测须正常准入且沿用原总截止和站点累计包络 |
| 服务／页停止与已经排队的世界发送相遇 | 发布 R，全站仅一个此前获准调用可在 R 后返回且输入≤K；匹配 B 后不再发受影响输出，raw-close 并独立核引用／连接／生产者实际退出，才报告停止完成。无 B 或退出未知保持受影响输出关闭；不虚构授权保存职责 |
