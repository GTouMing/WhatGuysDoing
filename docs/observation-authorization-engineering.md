## 二、先分清必须表达的语义

依据[跨重启与共享登录](<observation-design.md#L85-L88>)、[授权者任免](<observation-design.md#L104-L107>)、[摘要/文件/提交规则](<observation-design.md#L123-L128>)、[故障与时钟](<observation-design.md#L149-L153>)及[安全存量](<observation-design.md#L319-L320>)：

| 必须表达的事实 | 不能混同 |
| --- | --- |
| 授权者的可信玩家 UUID 与是否仍有管理资格 | 观察者、观察授权、OP 权限或仅昵称；移除管理身份不撤其独立观察授权 |
| 每份观察授权的独立身份和撤销结果 | 当前凭证是否有效；到期、轮换和交付失败不等于授权已撤销 |
| 当前凭证所属授权、非秘密编号、摘要、有限期限及失效结果 | 明文、Cookie、完整历史凭证列表；旧凭证不得因失败回滚或时钟改回而复活 |
| 新凭证的一次交付是否仍在等待、已有可信确认或已终结 | 普通等待不是失败；原文释放不是可靠失效；确认与落盘之间还可能中断 |
| 文件版本、可信保存的时间边界及恢复状态 | 文件可解析不等于包含最新撤销；文件内标记不能证明文件本身没被整体回滚 |
| 登录、每页观察、管理任务、原文与预览的独立寿命 | 登录不持久化；原文不写文件；预览不成为长期许可或授权锁 |

永久签发者关系、观察者游戏 UUID/昵称/备注、完整变更历史并非上述已选要求，不为凑表而添加。必要排障记录仍独立受 7 天/20 MiB 上限约束，写失败不等同授权存储故障；它不充当可回放的授权真源。

## 三、一个显式字段布局及其容量

### 布局候选，不是已选格式

候选采用紧凑 UTF-8 JSON、固定 ASCII 键和值表示；以下全是字符串字段，无任意文本、重复键或嵌套扩展。32 个十六进制字符只表示**非秘密标识**；凭证本身仍是已选的 32 字节安全随机秘密，摘要为 64 个十六进制字符。二十位十进制字段有前导零，值仍限定在实现支持的非负整数范围，不交给浏览器浮点数保真，也不允许溢出回绕。

| 授权记录字段候选 | 值宽度（bytes） | 用途 |
| --- | ---: | --- |
| `id` | 32 | 观察授权标识，不推导游戏身份 |
| `revision` | 20 | 最后一次持久变更版本；用于拒绝迟到结果和检测变更后恢复原值 |
| `grantState` | 1 | 授权有效/已撤销，与凭证状态分开 |
| `credentialId` | 32 | 当前凭证的非秘密编号 |
| `credentialState` | 1 | 无当前凭证/有效/失效；失效不是重新按当前墙钟即可变有效 |
| `digest` | 64 | SHA-256 摘要，不是原文或可找回副本 |
| `issuedAt`、`expiresAt` | 各 20 | 检查有限期限与最长 90 天；不延长固定登录寿命 |
| `deliveryState` | 1 | 无待交付/等待/已确认/失败终态，具体编码待核定 |
| `invalidReason` | 1 | 有限失效原因类别，不存任意错误文本或历史 |

无凭证等状态使用固定占位值；组合校验决定其是否有意义，不能把占位摘要当有效凭证。撤销、轮换、失效改写原记录；只保留当前凭证而不是为每次轮换增加墓碑。当前有效登录必须关联其授权和凭证版本，不能只查“该授权还有某个有效凭证”。

授权者候选记录只有 `uuid`（32）、`revision`（20）、`state`（1）；保留的已移除记录也计 64 名上限。文件外层候选包含固定版本、文件身份、全局变更序号、可靠保存的时间下界、有限恢复状态及两类数组。初始化仍是控制台明确操作，不以空文件、缺字段或默认值推导“首次安装”。恢复状态仅在可信保存后有意义，不是自动开通开关。

### 字节核算

全部字段为 JSON 字符串时，单对象大小为：`2 + (字段数 − 1) + Σ(键长 + 5 + 值长)`，分别对应花括号、逗号及引号/冒号。不含空白格式化；每条记录另保守计一个逗号和一个换行。

| 内容 | 本候选可复算的大小 | 原候选保守包络 |
| --- | ---: | ---: |
| 10 字段授权对象：键长合计 96、值长合计 192 | `2 + 9 + 96 + 50 + 192 = 349` bytes；含分隔 ≤ 351 | 512 bytes/条 |
| 3 字段授权者对象：键长合计 17、值长合计 53 | `2 + 2 + 17 + 15 + 53 = 89` bytes；含分隔 ≤ 91 | 256 bytes/条 |
| 1,024 条授权、64 条授权者、外层及元数据 ≤ 16 KiB | `1024 × 351 + 64 × 91 + 16384 = 381632` bytes | `1024 × 512 + 64 × 256 + 16384 = 557056` bytes，即 544 KiB |

因此，在**本候选语法及字段不变**的条件下，必要状态改写不会因增长历史而突破已选 2 MiB 文件上限；原 544 KiB 包络仍有 1,504 KiB 余量。这不证明剩余恢复语义已补全，也不证明磁盘可写、原子替换可靠或总内存可用。前次 413/197 bytes 算例与这里不是同一字段布局。

候选解析要求先限制实际读取字节至 2 MiB，再验证 UTF-8、完整单文档、字段/数量/长度、唯一 ID、合法状态组合、期限和序号范围；不先构造无界树再检查，也不截断超限文件取前半份许可。未知格式不能静默补宽松默认值。当前文件、同文件系统临时文件、当前/候选内存状态、编码/读取缓冲均分别计账：两份文件内容按既定单文件上限可达 4 MiB，文件系统开销另计；16 KiB 元数据余量不是临时文件或安全任务名额。

### 两个不能靠字段声明解决的问题

- **交付中断：**候选在新凭证可靠生效的同一状态中保存“等待交付”，然后才交付原文；可信确认后由同一有界任务保存确认终态，失败/未确认/到期则可靠失效。活跃运行中的正常等待不直接失效。重启不能重用丢失的原文或仅在内存中的确认；读到未闭合状态时先阻断该凭证并处理终态，不能直接放行。具体确认通道和该事务仍未验证。
- **过期、回拨与崩溃：**运行中已过期立即失去使用资格，持久失效与可信时间下界不能由当前墙钟重新推翻。超过 5 秒回退按已选全站关闭、旧凭证失效处理；不足 5 秒也不能复活已确认过期的许可。但若失效/故障尚未可靠保存就崩溃，仅有 `expiresAt`、内存标志或文件内 `recoveryState` 不能证明下次启动仍知道它。需要继续核定启动门、未完成事务痕迹及保存顺序；不得把“所有重启一律重新签发”偷偷选为解决办法。任意离线整体回滚仍不在可自动识别保证内。

## 四、16 个管理名额内的所有权候选

已选的是全站最多 16 个**等待管理任务**、每授权最多 1 个待执行更新，以及待交付原文全站 4/每授权 1；不是 16 个普通任务再外加安全队列。下面为了避免出队、I/O 中或等待交付后出现免费对象，候选进一步将执行中所有者和确定预留都留在同一本 16 名额账里，属于保守工程取舍，尚未批准。

| 分类候选 | 名额上界 | 使用及归还条件 |
| --- | ---: | --- |
| 普通管理/清理预览 | 8 | 含未提交预览、待准入管理及其执行中所有者；不生成排队秘密，不借安全预留 |
| 签发至交付终态的专属所有者 | 4 | 准入后、生成原文前取得；覆盖可靠生效、等待领取、确认落盘或失败失效，直到终态可靠完成及清理结束 |
| 其他已校验必要安全更新 | 3 | 独立授权的撤销/失效等；不占用已经承诺给交付终态的名额 |
| 全站安全关闭后的收敛任务 | 1 | 有界遍历在册记录、处理全局失效/恢复；不是给每个记录另排一项 |
| 合计 | **16** | 只是一个 8/4/3/1 算例；不证明最优分配、活性或运行容量 |

1. 签发任务从普通类别**转移**到交付类别，而不是同一授权出现两个待执行更新；转移失败就拒绝签发，不先生成秘密。原文数量与任务所有者数量分别计，原文已释放但失效尚未可靠完成时不能归还终态名额。最长 120 秒从原文首次产生计，不能因排队、确认或重试重新起算。
2. 同一授权同时至多一个更新所有者。若它等待交付时又收到已校验撤销，候选让该所有者接受更严格的“撤销/失效”目标，先阻断许可，再完成可靠终态；不另排第二个任务、不等领取超时。普通类别中尚未转入交付阶段的排队签发/轮换也适用：同一所有者提升为安全优先目标，不能让撤销等普通队列或因交付名额满而拒绝；分类转移仍须在 16 内，确实无法承接则走 Q146。重复请求只返回真实进行中/结果，不增长无界回调或等待者列表。如何提供有界最终反馈还须核定，不能把“已合并”当“已完成”。
3. 若较弱的保存已开始，后到撤销不能假称取消了磁盘操作；保持发送/认证阻断，在同一所有者中完成必要后续状态。迟到的交付确认只作用于匹配的授权/凭证/事务，不能复活已撤销许可。较弱保存完成不能覆盖此后设置的阻断，不能释放仍承担更强目标的所有者或报告整体完成。整文件保存还须使用串行提交时的可信基线：B 不能把在 A 撤销前构造的旧快照写到 A 已可靠保存的新状态之上；基线版本过时必须重建或拒绝，不仅检查 B 自己的记录。
4. 全局安全任务可持有限原因集合并遍历至多 1,024 条授权/64 条授权者，不给重复故障另开任务链；与各授权现有所有者交接或合并目标，不另排该授权第二个更新，不绕开串行保存，也不把已经开始的较弱 I/O 当作已取消。全站阻断保持到必要可靠状态和既定恢复条件满足。普通任务不能占其能力；已经校验的必要安全更新确实无法承接时立即执行[Q146 的既定出口](<observation-design.md#L342>)：停止认证及全站应用层世界发送，关闭观察，明确未完成，游戏继续。匿名未校验流量只有限流资格。
5. 槽位空闲不证明串行写入能推进；卡住的磁盘 I/O、未退出的旧任务和四个同时失败的原文都须真实计账。该保守分配可能较早拒绝普通工作或触发故障出口；不能仅凭 `8 + 4 + 3 + 1` 宣布不会耗尽，也不能私自均摊掉已有终态承诺。具体分配、有限 I/O 退出与持续故障恢复仍是工程门。

必要安全更新的受理和原文交付通道就绪是不同条件：通道未就绪可拒绝签发，但不能因此拒绝撤销。游戏内真实发起者、控制台可信本机领取者仍按各自证据核验；loopback、观察登录、OP 或普通日志反馈都不能替代。

## 五、固定清理预览不是锁住授权 60 秒

依据[Q145/Q146](<observation-design.md#L341-L342>)与[Q152](<observation-design.md#L362>)，以下为不增加政策的候选落实顺序：

1. **建立预览。**仅控制台可请求；先检查被选授权已撤销，且无有效凭证、登录、其他待执行更新或待交付原文；授权者只选已移除、仅为保留记录者。固定精确对象、数量和动作，取一个普通管理名额，最长 60 秒。预览不取各授权的更新所有权、不占安全预留、不持更新锁，也不保留明文。
2. **保存可重核依据。**每个选中对象保存身份、持久变更版本及相关资格变更版本；预览绑定当前运行期/文件身份及原始到期点。持久版本须在变更后又恢复原值时仍推进；清理后重建同名/同 UUID 记录也不能沿用旧版本。登录、任务和交付状态等易失资格由运行期版本覆盖，不强行写入授权文件。
3. **等待期间不锁对象。**其他合法管理可以推进；任何选中对象或相关资格变化会使原预览不可提交。新 C 变为可清理对象不会自动加入已显示的 A/B；超过 60 秒必须重新预览，确认动作不续期。
4. **提交前一次重核。**检查控制台资格、运行期/文件身份、时限、完整固定集合及所有版本/清理资格；任何一项变化或不合格都整批拒绝，不能跳过、扩大或只删剩余项。仅比较最终字段相等不足以排除“变过又改回”。
5. **全有或全无地取得本批所有权。**在串行协调点完成检查和所有选中对象的更新占用，失败不留下部分占用。它是一个有界批任务引用多个对象，每个授权仍至多一个待执行更新；资格检查不把本批自己刚取得的标记误当作原先已有更新。不会在预览等待期持锁，磁盘写也不占游戏 tick。
6. **可靠提交再报告。**根据串行提交时的最新可信基线构造只删除固定集合的候选文件；预构造快照的基线若已过时，须重建或拒绝，不能覆盖其他授权的新结果。不自动清其他记录，不截断容量。保存不可信按关闭观察路径报告未完成，而不是“内存删除成功”。提交快照与并发安全阻断的发布顺序必须证明，不能用一次方法返回当作事务保证。

预览选择本身也计内存。例：每项用至多 40 bytes 的定宽元组存对象类别、16-byte 标识及两个 8-byte 版本；最多 1,088 项为 43,520 bytes，8 个预览为 348,160 bytes（340 KiB），另加有界头部、容器与显示开销，全部在原模组内存预算内。这是元组内容算例，不是 JVM 堆测量或新的预览数量承诺；不复制八份完整授权文件或建立免费历史索引。

建立预览时“同一选中授权还有原文待交付”已经违反初始清理资格，不能用它当合法并存用例。真正需要处理的是预览后的对象/资格变化，以及实现把预览错误映射到唯一更新槽所造成的冲突。

## 六、保存、发送与释放的共同边界

Q155–Q156 已选顺序是：发布限制 R，立即拒绝对应新认证和输出生产；全站唯一一个此前获准、总输入≤K的写可返回；下一次写前由唯一输出所有者建立匹配 B 并回执；随后才开始该安全状态串行可靠保存；再完成旧登录失效、待发/必要引用清理及连接/所有者实际收束，全部匹配才能报告管理成功。没有 B 保持关闭并明确未完成。影响集合包括相关授权、登录、全部页和 HTTP 请求，不能只在连接建立或入队时核许可。

特别是当前使用应用层缓冲输出：**仍在应用缓冲中的字节没有进入“R 前已交 OS/代理”的在途例外**。R 后唯一一次≤K的残余不能改名为此前在途；部分 HTTP/WS 在 B 后 raw-close，不 flush、不补协议收尾，异常前缀未知不重放。[单一输出所有者专项评估](<observation-send-barrier-engineering.md>)给出严格前提下的次数/字节证明，已不再把发送生效点当未选政策；但 K、全入口迁移、固定平台/隐藏写者和有限退出的实际证据仍缺。

授权持久状态所有者、管理事务所有者、发送者和原文所有者不是一个生命周期。原文清空不能替代可靠失效；可靠撤销不能冒充已回收所有临时内存；日志写失败不回滚授权；内存阻断也不能冒充跨重启可靠撤销。已进入 OS/代理的字节及对方已复制的信息不承诺收回。

## 七、纸面冲突推演与后续门

| 场景 | 候选要求的处理 | 仍不能证明 |
| --- | --- | --- |
| 普通任务/预览已占 8 项，4 份原文同时到期 | 四个交付所有者已有各自终态能力；先阻断对应凭证、释放可访问原文，可靠失效未完成前不归还任务名额，不恢复旧凭证 | 磁盘能及时写、真正释放原文副本或 8/4/3/1 足够所有负载 |
| 交付确认与同授权撤销相撞 | 同一所有者收敛到不再授权；确认不得改回有效，也不增加第二个待执行更新；结果区分进行中与可靠完成 | 具体协调/写出屏障及跨崩溃持久结果 |
| 预览 A/B，A 变化后又恢复原值；另有 C 新近合格 | A 的版本变化使整批拒绝，B 不单独删、C 不加入；不得只检查最终资格 | 版本推进涵盖全部相关变更、无回绕及取得所有权的原子性 |
