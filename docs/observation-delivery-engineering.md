## 二、候选最小依赖闭包

### 分开“应用需要”与“呈现需要”

下表是工程候选，不选定线上字段、确认编码、线程或锁。每个可独立应用单元须能验证其所属运行期、许可、页观察、生效范围及相关基线代；实体还须验证连续活动，资源还须验证资源缓存代。不能用一个全局 `epoch` 混同这些寿命。

| 单元 | 应用所需闭包 | 后续呈现所需闭包 | 最小失效边界候选 |
| --- | --- | --- | --- |
| 单节完整基线 | 当前许可/页/范围/运行期；完整且有效的本节坐标、palette、bits、indices、光照及生物群系数据 | 本节状态及 overrides、实际读取的邻域/缺席状态、状态解释、模型、Atlas、GPU 池代 | 本节应用代及依赖它的增量；读到它的网格另失效，不自动停其他节或可靠事实 |
| 本节方块状态增量 | 同一有效本节基线与其已应用前序，状态 ID 的合法解释范围 | 更新后本节及受影响邻域网格；状态解释可能影响遮挡 | 缺失/错误基线不应用；重建当前本节，不能把旧增量写入坐标相同的新基线 |
| 单实体细状态 | 页有效范围、运行期、连续活动身份、相关实体基线与掩码前序；只包含该页允许的细状态 | 类型/通用模型、Atlas、选择与跟随状态、实例或整体几何 | 该活动的状态及依赖呈现；离开、移除、迁移和重生分别处理，不能借同 ID/UUID 接续旧活动或推断死亡 |
| 已确证交互事实 | 自足的发生期、结果、事发锚点/旧生效范围、必要活动身份及事发时已证实的最小来源上下文 | 有界列表文字；可选定位或画面不是接收资格 | 不依赖当前地形/实体基线、模型或动画；相关事实采集/接收失效才形成有证据边界的缺口 |
| 玩家定位索引、时间及连接状态 | 各自有效期与许可；不得给历史事实补当前身份或证明细采样 | 各自展示 | 不代替细状态应用 ACK、完成的新采样或可靠事实覆盖 |
| 类型、状态解释、模型与 Atlas | 实际资源键、资源代及端点许可；页相关结果另核页/范围代 | 引用该资源的网格/实例及 bind group | 真正通用且兼容的资源可共享；失效资源影响其所有实际使用者，不按“单页”硬切断共享依赖 |

完整节的应用不等描述符下载、邻段齐备、Atlas、GPU 或动画。解析完整性、长度/数量/引用校验及状态提交先成立，再发该有效单元的应用确认；不能像当前逐项改 Map 一样，在后项失败后把前项当作整批成功。多单元批次若允许部分应用，必须有独立可验证边界及确认覆盖；否则按完整批次失败。逻辑局部边界不意味着能拆分一个仍被持有的底层缓冲。

当前网格不是“本段加六个面邻居”即可概括：[mesher.js:125–134](<../common/src/main/resources/assets/what_guys_doing/web/mesher.js#L125-L134>)跨段查询遮挡/光照，[cornerOcclusionOffsets:55–71](<../common/src/main/resources/assets/what_guys_doing/web/mesher.js#L55-L71>)及[逐角使用:194–205](<../common/src/main/resources/assets/what_guys_doing/web/mesher.js#L194-L205>)还涉及边/角偏移。对当前一步偏移采样，可保守核查本段周围 `3 × 3 × 3` 段，精确关系是实际读集合及缺席状态；这不是要求补采、强载或固定保留 27 段。当前只标六面邻居的路径不能独自证明完整反向失效覆盖。邻域缺席只表示没有可用观察数据，不声明世界为空。

候选应用确认是有效单元/流水代内的有界累计覆盖，不是无条件的全页最大序号。首次/切换基线成功应用立即确认，其余最多合并 100 ms；不等待 GPU。编码时的候选旧值、已写值、已确认应用值必须可区分，不能直接把当前 Codec 的 `last` 当确认基线。依赖流水可有界提前发送，但仍必要的旧版本及前序必须计账；不为确认另保留重发事实历史。

## 三、逐对象所有权与字节口径

### 当前节负载能核算什么

设本节 palette 条目数为 `p`，索引位数为 `b`，索引字节数为 `i = ceil(4096 × b / 8)`。当前构建中 `p ≤ 4096`、`b ≤ 12`，见[位数及分配](<../common/src/main/java/github/gtouming/what_guys_doing/world/WorldSampler.java#L100-L116>)。

| 口径 | 静态有效负载公式/上界 | 不包含 |
| --- | --- | --- |
| 服务器节数组 | `4p + i + 4096 + 1024 = 5120 + 4p + i` bytes；上界 27,648 bytes | record、数组头/对齐、Map/key、构建临时容量及 JVM 回收滞后 |
| 当前完整节协议负载 | `17 + 4p + i + 4096 + 512 = 4625 + 4p + i` bytes；上界 27,153 bytes，见[编码字段](<../common/src/main/java/github/gtouming/what_guys_doing/net/Protocol.java#L34-L53>) | WebSocket/TLS/代理/网络头、编码工作空间；不是线上总量 |
| 浏览器打包节数组 | 与服务器数组公式相同；biomes 由 16 位线上值转成 `Int32Array` | 对象/Map/Set、overrides、可选展开 ids、网格暂存、GPU；ids 若实际创建另加 16,384 bytes |

编码工作空间不能按一个消息长度计：[Protocol.java:36](<../common/src/main/java/github/gtouming/what_guys_doing/net/Protocol.java#L36>)在当前两光照数组等长的路径中初始容量恰比完整负载 `L` 少 1 byte；[BinaryWriter.java:19–26](<../common/src/main/java/github/gtouming/what_guys_doing/net/BinaryWriter.java#L19-L26>)会扩至 `2 × (L − 1)`，[toBytes:98–100](<../common/src/main/java/github/gtouming/what_guys_doing/net/BinaryWriter.java#L98-L100>)再复制 `L`。扩容旧数组、构建的 4096 项 local 数组及 palette 去重容器也属于过渡成本；这是分配路径核算，不是实际堆峰值测量。

### 候选所有权与预算分类

| 对象/实际保留 | 当前或候选所有者 | 待发/额外未确认包络 | 总内存及释放边界 |
| --- | --- | --- | --- |

| 已应用当前实体/地形基线 | 对应页有效当前状态；共享底层必须有明确所有者 | ACK 后仅退出不再必要的额外版本/引用；当前本体不归免费内存 | 模组及每页 CPU 总预算，实体 ID/基线身份元数据也须有界 |
| 确认覆盖、依赖 key、队列节点与页句柄 | 每页独立；共享对象关联其所有消费者 | 有界元数据及引用开销计入，条目数不替代字节数 | 完成/失效移除后不能由旧回调重建；所需最大数量、编码及容器开销尚未核定 |
| 浏览器接收缓冲、复制节数组、overrides、两个索引 | 页面接收/应用过程、当前状态和具体派生使用者 | 服务端包络不冒充浏览器内存预算 | 每页 CPU ≤ 256 MiB；同一对象物理一次，两个索引各自的节点另计；中途失败暂存也计 |
| 描述符请求、模型缓存、Atlas 构建及位图 | 明确资源代的缓存与真实进行中的请求/Promise/构建 | 不以 pending 集合清空宣称工作消失；涉及世界交付的额外服务端对象仍归既有包络 | 浏览器 CPU/GPU；捕获数组、响应正文、位图和旧/新资源并存分别计，取消后直到实际结束继续归属 |
| 网格 CPU 暂存、池区段、GPUBuffer/texture/bind group | 当前构建/有效呈现、共享池/资源所有者 | 不等待它们才 ACK；但不因 ACK 免除资源成本 | CPU ≤ 256 MiB、GPU ≤ 512 MiB。区段可复用不等于 backing buffer 缩容，[removeSectionMesh](<../common/src/main/resources/assets/what_guys_doing/web/app.js#L1369-L1374>)只归还区段；按实际申请容量计 |
| 取消中的旧任务、写 I/O、回调及已分配旧资源 | 原尝试/任务直到实际退出；不能转给“无所有者”池 | 属于交付依赖的部分继续计入 4/32 MiB，其余仍受既有总预算 | 不以 Future、Abort 或关闭调用作为完成；峰值原始起点与回收截止不重置 |
| 事实列表／缺口与恢复候选 | 各自独立所有者及有限存量；公开模式没有观察登录存量 | 不为事实增加重放池；候选不持活动采样权 | 保留原5分钟／条数／字节与全站候选≤8；原每授权／登录各4撤出，不互借免费额度 |

候选计账采用两本有关联的账：每页归属保守足额，全站物理按底层分配去重；句柄和独立编码副本不能去重。只共享一个额外保留对象 `R` 时，A、B 各归属 `R`，全站载荷为 `R`，不是各 `R/2` 或全站 `2R`。若拆出两份独立载荷，则按实际两份计。A 失效只撤其引用，B 仍必要的对象不能释放。

既有当前缓存本体仅在总内存账物理计一次；若一个交付引用在当前版本替换后会迫使旧版继续存活，候选要求**发送前**在 4/32 MiB 内预留该版本容量。预留与物理已分配分别展示，不能等替换时才发现超额；未被交付引用的全部当前缓存不列入未确认账。每页待发/额外未确认实际占用加相应预留 ≤ 4 MiB，全站相应物理占用加去重预留 ≤ 32 MiB，仍处于模组总内存 ≤ 512 MiB 堆/≤ 768 MiB 含堆外之内，预算不是可相加的额外内存。

写后可释放的是**确实不再需要且无实际持有者的具体副本**，不是整条“已写”记录的所有成本；需要的基线/前序、确认元数据、进行中的写引用继续计账。不为等待 ACK 无理由保留可重放原文。逻辑断开、可复用、运行时回收及进程实际内存回落分列；对象头、容器、JavaScript 引擎与驱动成本仍需受许可的实际核算，不能以上述数组公式宣布总预算通过。

## 四、候选转换、发送屏障与截止

| 转换/触发 | 许可、依赖与发布边界 | 计账、时间及失败出口 |
| --- | --- | --- |

| 部分 ACK/等待确认 | 各独立流水只推进真实覆盖；共享错误对象的所有实际使用者属于失效集合，不硬限定单页 | 候选从实际应用层发送开始计龄，具体提交边界尚待核定：最早仍必要未覆盖依赖正常 1 秒/固定慢网 5 秒；覆盖部分不重置剩余原龄。待发 0.5/2 秒、硬包络、原总时限分别适用，先到先处置 |
| 基线缺失、应用失败或确认超时 | 先停止受影响依赖流水、使相关旧代无效，再撤队列/引用；重建当前，不跨代接旧增量 | 同次自动局部重试 ≤ 2；保留真实残留成本，不续峰值/信用。无此依赖的可靠事实继续；事实采集/接收失效另标有证据的缺口 |
| 普通范围切换/手动新尝试 | 先停止旧细状态发布并使旧任务/基线失效，再接纳最新完整意图。普通切换的旧范围已纳入事实仍按事发范围进入有界列表，不混入新范围状态 | 手动新尝试总时限从该次输入起算，但连续峰值、回收截止及流量信用不重置；无回填或自动恢复中断跟随。资源结果只在真实兼容资源代及服务／页有效性下复用 |
| 完全压力暂停/候选 | 停止活动细采样／流水并立即释放活动名额；候选全站≤8，满拒新、不挤已有者，无采样权；每授权／登录各4撤出 | 未入候选或自动轮次结束关闭观察连接，仅保留已允许的页内非实时信息；取消残留不免费。不可见或页资格失效释放候选 |

| 已识别短断流/重连 | 原页名额至多保留10秒，不继续细采集或积压；随后恢复须正常准入，不挤其他页 | 重连≤5次／60秒先到；不改变既有45秒断流识别边界，不与压力候选混用；不可见、页结束或页资格失效立即释放 |
| 服务／页停止或真实依赖失效 | R 直接拒绝相关新准入和生产；全站一个此前获准、总输入≤K的通道调用可返回，下一写前建立匹配 B。按真实依赖圈定影响页，旧范围事实也不能绕过服务停止；不存在共享登录集合 | B 后不补 HTTP／WS 后缀，实际待发／必要引用、连接及相关生产者退出分别核，未知仍占账。独立必要缓存保存另核，不建授权事务；已交 OS／代理字节不承诺收回，R后残余不改名为此前提交 |

候选失效顺序必须能落到具体机制，但本轮不选择锁或执行器：

1. 确定真实影响集合和原因：范围／应用代失败与服务／页／运行有效性失败分开，事实的事发范围资格与当前状态有效性分开。
2. 建立失效及发布／发送屏障，关闭该集合的新采集、排队、编码发布与后续世界发送资格；验证点不能只在入队时。
3. 此后旧回调只能完成清理，不能把旧结果写回当前状态、重新启用页或受影响输出、补历史或刷新采样新鲜度。通用资源也须按自身代及真实有效性验证，不盲目因页切换丢弃或复用。
4. 从待执行队列和依赖图撤去受影响引用，保留其他页真实必要的共享引用；取消进行中工作，但继续保留其实际计账。
5. 呈现侧立即撤销受影响旧 draw/实例的当前有效资格，清相应失效 CPU 索引和派生引用。普通移动仍可保留新范围中的兼容重叠状态；允许保留的旧地形必须有明确非实时标识、独立有界所有者并继续计账。共享 GPU 池是否保留复用与旧数据是否仍可作为当前画面绘制分别决定；资源替换也须撤掉真正依赖旧资源的呈现，不把不可使用误写为所有信息必须消失。
6. 只有实际持有者退出后才撤残留账；真实内存回落继续按既定峰值约束证明：最多 2 倍、≤ 90 秒，截止为 `min(完成时刻 + 30 秒, 峰值起点 + 90 秒)`。取消、重试和切换都不改峰值起点。

全入口迁移须覆盖当前已取得资格、等待写锁和处于 I/O 的旧任务；不能在保留这些直接写者的同时声称已有唯一输出所有者。[当前写/关闭锁顺序](<../common/src/main/java/github/gtouming/what_guys_doing/web/WebSocketConnection.java#L55-L95>)不是屏障证明。Q155–Q156 已接受 R 后全站唯一一次此前获准≤K的写及下一次写前的匹配 B；不是等待同一阻塞写锁或一个 closed 字段。B 后不续受影响应用后缀；K、全入口迁移、固定平台及实际退出仍待证。B 与必要引用、连接及生产者实际退出分列；仅在确有必要缓存持久职责时另核保存顺序，见[输出工程稿](<observation-send-barrier-engineering.md>)。

| A、B 共享额外旧基线 `R`，B 正常 ACK，A 超时 | A/B 各足额归属 `R`、站点物理一次；A 的 1/5 秒到期先失效其依赖流水再撤引用。B 的当前有效基线若无失败依赖继续；若 `R` 本身错误则所有实际使用者都失效。A 的终止不提前释放 B 仍必要的数据；独立编码副本另计 | 每页选择在服务端发生；队列、编码、确认和共享引用的真实原子边界及最坏成本 |

## 六、本轮完成与下一层缺口

本轮完成实际图、对象分类/可证负载核算、候选转换与五个纸面推演；不再只留下抽象审查准则。没有证据要求放宽预算或改变已选产品政策；当前实现不符应留在工程缺口，不另造偏好问题。

还不能核定完整工程方案：

- 最小单元的确切协议/应用提交边界、累计确认表达、活动身份接入及最大元数据数量；本节局部失败不意味着可免费拆分共享缓冲。
- 逐页选择与事实事发范围过滤、实际反向依赖、同步发布/失效边界及迟到回调；尤其当前实体并集输出、`sent` 与应用确认混同、切换残留没有通过保证。
- 对象头/容器/编码副本/回收滞后与 GPU 分配的完整容量，八页重叠/不重叠及慢页最坏并存；保守归属可能更早限流，其性能可行性须证明，不能默默改成均摊。
- 阻塞写、取消、真实释放、发送屏障、探测资源恢复及所有性能门；数组公式、方法返回和纸面推演都不关闭它们。[发送屏障工程稿](<observation-send-barrier-engineering.md>)已补当前 HTTP／WS 输出尺寸；旧授权→页→连接树仅供历史追溯。Q165／Q170 已确认每活动页权重 1、普通公开 HTTP 单一总桶权重 0.5；[归桶交接与有限阶段候选](<observation-send-barrier-engineering.md#L290-L332>)要求 101 全推进、当前页资格和唯一所有者采纳分别成立，提交前 HELLO 与读线程控制均无输出旁路。零写耗桶机会并撤出可服务快照，不因换连接、旧 ready 或新轮立即重试；阶段成员与已耗机会／未访问游标跨普通唤醒和信用中断保留，HTTP 独占段另计，页仅耗尽阶段机会或枚举结束不许可独占；采纳前置不得依赖被挡住的 HELLO／Pong 或其回执。原构建／待发／依赖及峰值截止不延长，不发明普通 HTTP 的应用 ACK。具体算法、协议和注册策略仍待核定；机会份额、有限 17 次竞争调用及 K 切片均不证明实际字节比例、无饥饿、固定平台成本或真实退出。
- [旧授权字段、管理预留与清理稿](<observation-authorization-engineering.md>)及[旧凭证恢复稿](<observation-restart-engineering.md>)仅供历史追溯，不再作为公开观察的身份、可靠授权保存或首故障留痕门。可信构件、K／固定平台、全入口输出所有权、未知缓存写者、双加载器成功事实及实际部署仍须独立证据，见[现行工程分支矩阵](<observation-engineering-gates.md>)。
