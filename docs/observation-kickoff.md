## 1．用途、状态与阅读顺序

本包承接[现行设计](<observation-design.md>)、[统一术语](<../GLOSSARY.md>)及[R19-Q162／ADR-0011](<adr/0011-public-read-only-observation.md>) 的公开只读修改。**观察凭证、登录、授权存储、秘密交付及身份限额不再建设；这些旧段落只保留历史追溯。** Q159 有限生产、全站／每页包络、采集事实与实际收束继续；R20-Q163–Q165 已分别确认正常启动／重启在 enabled 且真正就绪时自动公开、显式对外绑定内置数据端口，以及活动页等份轮转与普通公开 HTTP 单一有限桶共享总预算，见[公开访问合同](<observation-public-access.md>)。Q154 每次人工开通仅留历史；配置关闭、真实故障、残留未退出不能绕过；R21-Q166–Q169 已分别确认故障消除／相关旧输出与写入收束／重新就绪后的有限当前重建、单纯墙钟回拨只告警、运营者反向代理负责 HTTPS/WSS／证书，以及仅服务器控制台／受控配置管理。整站重建包络及具体代理产品／配置仍待工程核定，不扩大本轮许可。本包把后续工作映射到文件、接口、预算与验证，但不表示完整工程已确认、产品已获准实施或验证通过。

本次范围只有设计文档及只读文档完整性检查：不修改产品或验证源码，不构建、不运行产品检查脚本或游戏，不启动监听、不联网验证、不修环境、不部署、不提交代码。V1A/V1B 保持停止；本包不授权第三次同环境启动尝试。

### 2.1 迁移必须覆盖的出口清单

HTTP 的 101、200、202、204、304、400、404、405、503 及静默断连；世界／索引、已定义状态与资源、模型／类型表／方块解释、瓦片、皮肤／披风和页面／资产；WebSocket 数据、应用 Pong、控制 Pong／Close 和异常清理。当前 101、皮肤200、披风200、资产304、页面304是统一响应之外的直写路径，详见[输出清单](<observation-send-barrier-engineering.md>)。公开路径不新增登录／退出端点；内部路径、错误或活动诊断须先分类与缩减，不能因旧代码存在便公开。

逐资源依据 Q162 的定义路由合同判断可公开输出，不把目录、扩展名、ETag 或状态码当公开资格。原 Q53 身份拒绝与登录控制调度退出；R20-Q165 已定普通公开 HTTP 一个有限桶、活动页等份轮转且共享总预算；同页多连接不加份额，不制造授权份额或自然人识别，实际连接关联仍待工程核定。

## 3．所有权与非阻塞协作合同

### 3.1 候选责任图

```text
游戏主线程：真实游戏读取/最终事实、页范围生效点、不可变采样/事实
    ├─读取单调限制快照；发布 ScopeActivated / Sample / Fact
    └─不等待网络、文件、join 或跨 I/O 的锁

限制发布入口：已校验安全事件 → 原子收紧限制 R → 唤醒输出所有者
    └─不用可能被普通任务占满的队列；不能被旧许可覆盖

唯一网络输出所有者：连接/Selector/协议游标 + 页交付控制状态
    ├─接纳有界请求与完成回执；准入、依赖/ACK、字节账及公平调度
    ├─发布匹配 B；只它可发起 write/raw close/注销
    └─不做游戏访问、磁盘读取、压缩、模型/PNG 构建

有界生产任务：不可变输入和明确租约 → 不可变结果 + 原代次 + 实际容量
    └─无 socket/OutputStream；完成时由所有者复验，过期结果只清理

独立必要缓存写者：来源／缓存代次 + 有界输入 → 发布／终态回执
    └─只在确有持久职责时存在；独立核发布、晚到作用和实际退出，不创建授权保存所有者

浏览器主应用所有者：校验 → 提交可用单元 → ACK → 独立调度呈现
    └─CPU/异步任务/共享资源/GPU 各有真实所有者与退出条件
```

页交付控制状态候选放在网络输出所有者，消除当前 reset/encode 并发；耗时编码在有界工作任务中基于不可变基线进行。完成结果只可由控制所有者提交，不能让 worker 改变“已应用基线”。这不要求所有数据生产都在网络线程运行。

游戏线程是**范围实际生效与事件时刻资格**的权威。网络收到新意图后，只保留最新完整请求；游戏在有界工作点发布匹配范围代与生效序号，随后数据携带该代。已进入旧范围的事实按旧资格处理，不能在发送时用新范围重筛而丢掉或越界。服务／页停止限制另可立即收紧任何代的资格。

### 3.2 候选跨所有者消息

| 消息/回执 | 最少内容 | 接收方必须验证 |
| --- | --- | --- |
| `RestrictionSnapshot` | 单调限制代、受影响服务／页／范围／连接、有限原因和关闭状态 | 只收紧；有限存量；release/acquire 可见性。Selector.wakeup 不是内存可见性本身 |
| `ViewIntent` / `ScopeActivated` | 运行期/页、请求代、维度/中心/半径、服务端生效范围代与顺序 | 不可变整体；旧意图不覆盖新意图；范围生效才纳入新范围事实 |
| `BuildLease` / `PreparedUnit` | 运行期／页／范围／基线或资源代、输入依赖、预留、实际底层分配、输出分段 | 先有容量再生产；完成时重核全部相关代；旧任务直到真实结束仍计账 |
| `BarrierReceipt` | 精确限制代与影响集合、取消写资格/丢弃应用后缀的结果、仍在退出的句柄 | 没有旧直写者；含 accepted 未分配连接；受影响通道已 raw-close 或隔离且仍计账。它不是回收/持久保存回执 |
| 独立缓存发布／实际退出回执 | 来源／缓存代次、所属任务／句柄、实际发布或退出结果及未知作用 | 迟到结果不能恢复旧代；分别核输出屏障、缓存发布和任务退出，不用单一成功回执包办 |

事务目标、工作队列、完成回调和等待者也必须有界。没有可用槽位不接受新普通工作；必要安全目标无法承接走 Q146，不能另加无界“紧急队列”。

## 4．状态机、顺序与失败出口

### 4.1 公开服务与页停止

| 当前阶段 → 触发 | 必须动作 | 可以报告的状态 |
| --- | --- | --- |
| 正常服务器启动／重启 → 准备／公开 | 核定配置、有限容量、实际网络所有权和缓存来源；新运行不接纳旧页结果，不恢复历史列表。R20-Q163 已确认 enabled 且真正就绪时自动公开，替代 Q154 每次人工开通 | 未就绪／准备中或就绪后公开；配置关闭、真实故障、残留未退出不能自动越过 |
| 页停止／范围失效／服务故障 → R | 直接收紧受影响的新准入与输出生产；完成结果复验所属页／运行代，不经普通满队列延迟限制 | 受影响输出关闭中，游戏继续 |
| R → B | 全站仅一个在 R 前已获准、总输入≤K的调用可返回；返回后下一写前处理限制、撤写兴趣、弃后缀并发匹配回执 | 输出屏障成立，不是任务／连接退出或物理回收完成 |
| 匹配 B → 实际收束 | raw-close／注销受影响连接，停止新生产；仍持引用的任务和回调继续计账，分别取得真实退出／释放证据 | 全部匹配才报告受影响停止完成；无回执保持关闭／未完成 |
| 缓存写者／旧完成的作用未知 | 不允许旧结果重新发布、不复用未知所有权和容量；有实际共享文件替换职责时独立核其发布、串行与失败边界 | 未完成／未知，不用换运行号、cancel或重读成功冒充无旧副作用 |
| 准备正常停止 | 关闭新准入和生产，执行匹配限制，收束连接及生产者；必要共享缓存发布独立完成或标未知 | 干净停止／残留未完成分别报告；不维护凭证收束标记或重签事务 |

`R/B/W/K` 是工程记号，不新增领域术语。W 是调用正常报告接纳的前缀；异常按本次 [0,K] 未知，绝不重放。部分 HTTP/WS 直接断开，不补正文、结束块、Pong 或 Close。R 前进入 OS／代理的字节不受 K 限制，也不承诺收回。

R→B 依赖唯一写者、直接内存可见的限制、一次检查至多一次调用、每种返回后优先处理限制及无隐藏写者。**全站一次，不是每连接一次，也不是硬墙钟、内存释放或浏览器送达保证。** 公开模式没有授权保存任务；只有另有真实可靠保存职责时才另核 B 后的保存顺序，见[ADR-0010](<adr/0010-single-owner-send-barrier.md>)。

### 4.2 原凭证管理、秘密交付与首次标记（历史，不实施）

[R19-Q162](<observation-design.md>) 已退出授权串行事务、16个管理名额、120秒秘密、60秒授权清理预览及 Q153/Q158 凭证恢复。旧方案和首次无痕反例保留在[授权历史稿](<observation-authorization-engineering.md>)及[重启历史稿](<observation-restart-engineering.md>)；不能当作公开模式的待建接口、资源额度或开通门。取消这些职责不是证明旧持久性成立，也不忽略实际缓存写者的未知副作用。R20-Q163 已确认正常启动／重启自动公开；R21-Q166 已确认真故障只停观察、游戏继续，仅在故障消除、相关旧输出／写入已收束且重新就绪后有限自动重建当前；未知或耗尽保持关闭并提示管理员，不无限重试或回放。整站次数／时限／成本待工程核定，不套页级重连／压力探测数值；Q167 单纯墙钟回拨只告警，具体计时边界见第7节。

### 4.3 页状态必须分轴

服务就绪、连接存活、范围生效、详细流新鲜度、基线应用、呈现完成、事实覆盖与资源压力是独立轴。不能用一个 READY、心跳或“收完消息”替代它们；没有登录有效性轴。

| 触发 | 范围/依赖转换 | 名额、保留与时间 |
| --- | --- | --- |
| 首次观察/新范围生效 | 首次建立页标识；新范围独立建代并停止旧细状态发布，普通移动可保留新范围内兼容重叠状态；需重建的单元基线独立建代，新采样与可信应用后才可称当前 | 正常活动准入；适用15/45/60秒总期限从原输入计，不按步骤续期 |
| 应用成功/ACK | 完整单元提交后确认，同一单元/基线代的连续覆盖才前进；首次及切换基线立即，其余≤100 ms | 仅释放被覆盖且不再必要的额外依赖；当前本体仍计总内存 |
| 基线缺失/部分错误/确认超时 | 停实际依赖闭包、废旧代、重建当前；无关可靠事实继续 | 局部可重试≤2次；未覆盖依赖原龄、待发原龄、总截止均不续 |
| 普通切换的旧范围事实迟到 | 同一有效页活动且事发资格成立，可进有界旧范围列表，保留原锚点/维度/运行期并标迟到 | 不进入新范围实时状态；不为它另存重放历史 |
| 不可见 | 停详细订阅、连接和渲染；结束该页活动/候选资格，取消并核清任务 | 不把失焦等同不可见；未退出资源继续归原所有者 |
| 已识别短断流 | 不继续本页细采样/积压；恢复需新当前状态，跟随按既定手动规则 | 原活动名额最多保留10秒；重连≤5次或60秒，先到停止；不改变45秒断流识别 |
| 压力完全暂停 | 停细采样/流水并释放活动名额；候选没有采样发送权 | 全站候选≤8，满拒新；未入或耗尽本轮关闭观察连接，仅保留现行规则允许的本地非实时信息 |
| 有限探测/恢复 | 可见、服务就绪、取得正常活动准入及全站探测权；真实负载连续证据才升一级 | 遵守第7节探测包络；按 R20-Q165 页等份边界竞争，候选底层次序仍待核定，不自动恢复已中断跟随 |

## 5．协议草案与应用提交合同

### 5.1 版本与生命周期标识

当前[协议常量](<../common/src/main/java/github/gtouming/what_guys_doing/net/Msg.java#L10-L25>)是 v2；下面称 vNext，**不预占版本号、opcode 或宣称兼容**。同发布套件前后端需匹配；不兼容明确停止，不无限重连。旧实现中缺失按页有效性或应用 ACK 的路径不能作为回退；公开访问本身不是旧兼容路径，也不是缺陷。

下表给出可核算的**候选编码**，不是新增已选格式。整数候选小端，UUID／随机非秘密代号用原始16 bytes；64位序号／代号在 JavaScript 用 BigInt 或字节表示，不能转 Number 再拼接。计数溢出不得回绕复用旧代。当前公开模式不认证观察者；页／运行／范围代只关联状态和拒收迟到结果，客户端回传的代或页 ID 不增加容量、范围或管理权。

| 层次 | 候选字段 | 校验和寿命 |
| --- | --- | --- |
| 页消息公共包头 | `type:u8, revision:u16, payloadBytes:u32, runId:16B, pageId:16B, pageGeneration:u64, scopeGeneration:u64`；合计55 B | 长度先核定再分配；服务端关联当前连接／页／有效范围及资源；运行、页、范围独立失效。这只是候选字段重述，不是凭证或最终schema；HTTP/WS自身头另计 |
| 可应用单元边界 | `unitKind:u8, unitBytes:u32, unitKey:定宽分类键, baselineGeneration:u64, sequence:u64, previousSequence:u64, sampleTick:u64` | 每个单元可独立完整验证；键按节坐标或活动身份定义，不接受无界文本；基线代是单元的，不用全页最大序号替代 |
| 节基线/增量 | 维度+节坐标、palette/bits/indices/光照/biomes；增量含同基线前序及有界记录 | 先验证数量、位宽、索引、坐标及全长再原子提交。缺基线不应用；同坐标新代不继承旧增量 |
| 实体基线/增量/移除 | 运行期内连续活动身份、当前维度、类型、掩码、前序、已证实状态；玩家身份另字段 | netId/UUID不代表连续活动；removed只终止匹配活动，不能推定死亡或删除同编号新活动 |
| 新采样进度 | 采样序号/tick、覆盖的有效单元/范围及与当前基线的关系 | 即使值未变化，新且完整可用的采样仍推进新鲜度；旧包迟到、心跳和ACK不推进。不能直接相减两机器的单调时钟 |
| 事实 | 页内事实身份/顺序、运行期、事发范围代、维度/锚点、结果类别与已证实结果、当时可证相关方及未知标记 | 依据事发范围，不依据发送时范围/模型/细实体截断；不附外侧持续细状态；内部全服顺序不用于推算本页漏收或暴露外侧数量 |
| 缺口/覆盖状态 | 受影响事实流/范围、原因类别、可证起止/数量及独立未知标记 | 未就绪、传输缺失、正常列表淘汰分开；恢复当前不是补齐历史，恢复可信采集/接收覆盖才闭合持续中断 |
| 资源引用/完成结果 | 实际资源键、资源代/来源标识及实际需要的运行／页／范围代 | 通用兼容资源可共享；挂接结果时再核服务／页及资源有效性，不能只在fetch前检查 |

公共包头不意味着所有消息都需要相同适用范围；运行级协商和通用资源应有各自明确 schema。最终 schema 必须写出逐类型字节表，以及哪些上下文由连接绑定、哪些在线传输，不能用“可选任意扩展”逃避容量核算。55 B只核算这一个候选包头，不改变现有消息大小结论或选定 K。

### 5.2 ACK 草案

候选 APPLIED 是公共上下文加 `entryCount:u16` 和有界条目，每条明确 `unitKind / unitKey / baselineGeneration / appliedThrough:u64`。一个条目只表示该单元同代从可信基线起**无缺口连续应用**的覆盖；不同单元各自累计。较大确认集合分成多个完整、各自不超过既定4 KiB的入站消息，不截计数、不让一次解析无限分配。

1. Reader先检查消息总长、条目数可容纳性、字段/引用合法性及完整消费；在有界暂存构建，再提交独立单元。若一批不能独立验证各单元，整批失败，不承认前半批已成功。
2. 首次/切换基线提交立即ACK；其余最多合并100 ms，不等描述符、网格、Atlas、GPU或动画。ACK定时器只有一个明确页所有者，退出必须清理。
3. 服务端只接受已完整输出、同许可/页/范围/单元/基线代且前序可证的累计覆盖。未来、旧代、重复和跳过必要前序的ACK不推进“已应用”。部分覆盖不刷新其他未覆盖依赖年龄。
4. 编码候选值、实际已写值、已确认应用值分别保存身份；纯编码不能提前提交“已应用基线”。有界流水允许发送，但必要旧版本/前序不能释放。
5. **发送计龄埋点候选：**按输出游标映射单元协议字节范围；第一次获得正写返回的相应调用，以其入口单调时刻作不晚于实际提交的保守起点。共同头覆盖多单元时须明确归属及保守计龄成本。零写不启动或刷新实际发送进度；异常提交未知即停相关流。具体埋点仍需合同测试和工程确认，不能用入队/编码完成起算，也不能等整批全部写完才起算以放宽时限。
6. 必要未确认依赖正常1秒/慢网5秒、待发0.5/2秒、硬字节和原构建期限独立生效，先到先处理。待发原龄不因合并、移动队列或部分写重置。无确认不等于需要保留可重放事实原文。

### 5.3 应用依赖与呈现依赖分开

节应用不等邻域、描述符或GPU；网格却依赖实际读过的本节、边/角邻域及缺席状态。当前一步偏移可用周围3×3×3作保守反向依赖核查，**不是额外采集/加载/保留27节的许可**。实体渲染依赖活动及资源；事实文字不依赖网格或动画。详见[最小依赖闭包](<observation-delivery-engineering.md#L55-L74>)。

候选为每个派生结果保存有界依赖键和反向使用者。失效顺序是：停相关发布/采样资格 → 废代并拒迟到结果 → 停实际派生使用者 → 撤必要引用 → 验证真正退出/回收。共享错误资源须覆盖全部实际使用者，不能假定只影响一页或只影响六面。

## 6．逐对象预算与生产硬界

### 6.1 双账及预留算法

| 对象 | 页归属账 | 全站物理账及真实退出条件 |
| --- | --- | --- |
| 当前共享采样/节缓存 | 不是全部塞进待ACK账；交付可能导致旧版额外保留时先预留 | 当前本体计模组总内存；最后引用断开与运行时回收分列 |
| 多页共享旧帧/基线/底层数组 | 每个仍依赖的页按完整被保留底层分配足额归属 | 底层物理只计一次；各页引用/队列节点另计；最后实际持有者退出才能释放 |
| 输出切片、writer局部变量、编码工作区与结果 | 待发/必要未确认及相应预留均进4 MiB | 切片不只按remaining计；独立编码副本、扩容旧数组与最终复制分别计 |
| 已应用当前基线 | ACK只消去不再必要的额外版本/引用 | 当前状态仍计总内存，不成免费池 |
| ACK、依赖键、反向关系、任务/页句柄 | 元数据和容器容量也计，不用条数替代字节 | 数量与单项最坏大小都需核定；旧回调不得重建已废节点 |
| 浏览器接收/复制/overrides/索引/资源/网格 | 不由服务端4/32 MiB代替；按本页CPU/GPU预算归属 | 对象实际一次、索引节点分别计；池可复用不等backing缩小，destroy调用不等实际显存回落 |
| 取消中任务/Promise/I/O/旧图集与缓冲 | 保持原任务/尝试归属；与交付相关者继续进4/32 MiB | Abort/Future取消/清队列/关闭请求不是实际退出；不能转入无所有者池 |

候选分配流程：计算最坏新增载荷与元数据 → 取得页/站点容量和任务槽 → 构建 → 完成时核对代与实际容量 → 接纳或只清理 → 在真实引用退出时释放占用/预留。预留量与实际分配分列，但不能互相重复制造可用空间。

约束为每页待发+必要额外未确认实际占用+相应预留≤4 MiB、全站同类物理去重占用+去重预留≤32 MiB，仍包含在模组512 MiB堆/768 MiB含堆外预算里。共享一份大小X的旧对象给A/B时，两页各归属X、站点载荷X；若编码出两份，则物理是两份。不能均摊每页成本或将32 MiB加到总预算之外。

### 6.2 已知尺寸与未闭合生产项

| 项目 | 当前静态依据 | 开工前必须补的工程合同 |
| --- | --- | --- |
| 完整节 | palette p≤4096，b≤12；服务器/浏览器打包数组`5120+4p+512b≤27,648 B`；当前线载荷`4625+4p+512b≤27,153 B`，WS帧≤27,157 B | 新协议额外字段另加；对象头、容器、构建local数组、编码扩容与副本另算；不能证明总内存 |
| HELLO/维度元数据 | 当前`13+Σ(9+V(UTF8名称字节)+名称字节)`；维度数/名称总量无统一项目硬界 | 固定构件下维度/高度/名称/解析计数及单项/总元数据上限；半径8不等于高度/所有描述符有界 |
| block/entity | 当前block为`7+17N`；entity计数/removed/name仍可无界；u16不限制循环 | 独立记录边界分批，名字/计数/掩码/身份/基线版本数/反向依赖全部封顶；不截断字段伪造完整消息 |
| HTTP和资源 | 当前有完整JSON/模型字符串、PNG数组及副本；资产`Files.size→readAllBytes`不是严格上限 | 实际边读边限额、有限图片像素/解码容量、目录/路径/描述符总量、头部大小和任务并发；输出及物化容量分别核算 |
| 原授权文件布局（历史，已退出） | `1024×512+64×256+16 KiB=544 KiB` 仅为旧方案算例 | 不建文件、凭证或登录存量；不把撤出的预算自动转为新页或缓存容量 |
| ACK/作用域/活动/回调 | 字段候选已有，完整节点数/容器和真实运行成本尚无证明 | 给出最大活跃单元数、版本数、注册表/活动身份及任务残留上限和拒绝路径；不能先写无限容器、后看内存 |

未定上限不得填无限大默认值。若某不可拆对象不能进入既定包络，要有独立应用分批或已选拒收/降级/暂停出口；影响用户承诺的新截断必须带证据重议。四类事实20/100的验收强度**不是**可用于静默丢弃的产品事件上限。

## 7．保留硬限额与已确认匿名作用域

本节是 Q38–Q159 保留条款及 R20-Q165 的实施检查索引，全部是约束或目标，不是当前实测能力。观察身份额度已撤出且不转移扩容；已选的是页等份与普通公开 HTTP 单桶，低层调度仍为候选。每个实现常量须记录来源、计量点、作用域、触发动作和不可重置的原起点。

| 类别 | 保留数值／已选规则与待核定项 | 越界或失效动作 |
| --- | --- | --- |
| 详细范围/采样 | 半径默认4、最大8、最小0；自然可观察高度；实体正常每2tick，非目标降至5/10tick，目标优先2tick；玩家索引1秒 | 不诱导加载/保留；最低降级半径min(请求,2)，仍不可维持则暂停 |

## 8．唯一输出所有者的候选调度合同

以下具体循环次数、游标与零写处理是工程候选；已选的是单一所有者的R/B语义，以及R20-Q165／R22-Q170的每活动页权重1、普通公开HTTP单一总桶权重0.5并共享总预算。原授权／PUBLIC公平树仅为历史，不把政策接受写成具体调度通过。

1. 每轮先处理单调限制，再按accept→read→write做有界普通工作；每次write前复核，返回后的第一动作再复核。R/B限制处理不占普通工作配额，但Pong／Close等协议控制输出仍消耗合法桶机会、K和全局信用。
2. 原 `U32+H16+P8+Q8≤64` 是身份方案的条件算例，不是64连接许可。[P0](<observation-production-capacity.md#L141-L142>)另提所有accepted／握手／活动／idle／closing／旧连接合计32及工作描述符64，仍未核定。HTTP→WS、活动页→候选先取得目的容量，转移全程计账；满16个HTTP响应槽不能免费构造第17个503，无真实容量走既定拒收／关闭出口。
3. Q165／Q170已确认同页多连接不加份额，全站active≤8，满额拒新不踢合格旧页；不识别账号／IP／指纹，同人可多页，不复活身份额度或扩容。[归桶交接候选](<observation-send-barrier-engineering.md#L294-L307>)要求101全部按正常返回n推进后，由唯一所有者复核当前页资格并一次提交HTTP→页归属；提交前不发HELLO或WS控制。采纳后HELLO、应用PONG、WS Pong／正常Close和数据共享页桶，同页资源HTTP仍归总桶；无空档、双份或免费控制桶。
4. 每机会最多一次 `SocketChannel.write` 或gathering-write，全部buffer的remaining总和≤K，含HTTP／WS头；不是一次native syscall保证。[两阶段机会候选](<observation-send-barrier-engineering.md#L309-L319>)只对有限竞争枚举有 `|S1|+|S2|+a≤17` 条件界，稳定同一p页才为 `2p+1`；阶段成员及已耗机会／未访问游标不被准入、wakeup或信用不足重置。HTTP独占服务另计，不积攒恢复竞争后的机会；页仅用完本阶段机会或枚举结束，不许可独占。机会份额不保证实际字节或完成时间。
5. 零写消耗所属页／HTTP总桶机会，不扣字节、不推进游标、不续年龄；连接当场退出可服务快照，换同桶连接不退还机会。旧level-ready、普通wakeup、新轮或重建快照不单独许可立即重试，须有效可写条件或原截止导出的有界重试；注册策略仍待平台核定。partial仅按实际n推进，异常前缀未知、不重放。
6. 同连接不交错两个HTTP响应或两个WS帧。单个FIN帧可跨多次≤K通道调用，但切片不是插入Pong／Close的边界；Q101控制优先仅在合法的新帧／响应边界，必要近景进度仍沿原截止。R后弃受影响后缀raw-close，不为控制补尾；机会账、实际字节账和真实资源账分列，K不界完整分配、native工作或实际退出。

K、selector等待、向量数和零写重注册策略仍须平台事实与测量支撑。4/16/64 KiB 的[调用次数算术](<observation-send-barrier-engineering.md#L191-L197>)已形成[16 KiB 起始纸面评估候选](<observation-send-barrier-engineering.md#L225-L238>)，并补[按具体核验卡角色固定的平台清单](<observation-send-barrier-engineering.md#L240-L257>)；仍没有安全—性能通过或最终 K，不在本包填默认值，也不恢复 V1 或授权 V2。
